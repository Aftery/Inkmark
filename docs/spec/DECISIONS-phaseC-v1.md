### D-3 的具体含义（写给架构师的硬要求）

用户不接受"调用系统打印对话框让用户自己存 PDF"。必须做到：

- 应用内点击一次 → 直接产出 `.pdf` 文件（走系统保存对话框选路径）
- 需要程序化控制：**分页、页眉页脚、目录**（目录为 P1，可降级但要单独说明）
- 现有 `window.print()` 链路保留为降级后备，不作为交付形态

## 四、P0 绝对规则（全期适用，违反 = 退回重做）

1. **禁止 emoji 作功能图标** —— 一律走已锁定的 `AppIcon.vue` + `paths.js`。新增图标需按 ADR-001 采集流程从 `lucide-static@1.48.0` 逐字摘录，不得凭记忆重绘，不得引入第二套图标库。
2. **禁止紫色→粉色渐变**主视觉。
3. **禁止 AI 模板味**：空洞占位文案、硬编码颜色（豁免：`export/exporters.js` 的自包含导出模板，见 ADR-002）、弹跳缓动。

### 门禁判据澄清：区分「使用」与「引用」

emoji 扫描正则命中 ≠ 违规。门禁必须区分两种情形：

| 情形 | 判定 | 例 |
|------|------|-----|
| **使用** —— emoji 承担功能图标职责，出现在 UI 代码 / 设计稿 / 产物 HTML 中 | **违规，退回** | `App.vue` 工具栏写 `<span>📂</span>` |
| **引用** —— 在文档中作为「违规证据」被列举或论证 | **豁免，必须保留** | ADR-001 §14 列出 `📂 🗂 💾` 说明待替换；本文档 §四 引用需求中的 `🎉` |

判定要点：删除该 emoji 后**证据是否失效**。失效即引用，保留；不失效即使用，退回。
引用性 emoji 仅允许出现在 `docs/` 下的 Markdown 文档中，**绝不允许出现在任何代码文件或产物 HTML 中**。

### 特别警示：界面示意中的 emoji 是占位符，不是设计

需求文档的界面示意里出现了 `🎉 欢迎使用 Inkmark` 与顶栏 `🖊 🌙 ☰`。**这些一律不得直接落地**——
- 正文里的 `🎉` 会污染 `DEFAULT_DOC`（这正是 `20c722a` 修掉的违规项）
- 顶栏三个符号必须映射为 `AppIcon` 的对应语义图标（如 pen-line / moon-sun / panel-left）

## 六、核心需求（三句话定格）

1. **把 Inkmark 从「能编辑的 Markdown 工具」做成「写得爽的个人写作应用」**——WYSIWYG 即时模式为默认，标记符在非光标行隐藏，光标行显形。
2. **视觉上建立可切换的三套气质**（浅色 Indigo / 深色 / 纸感赭石衬线），用一套 Token 系统驱动，跟随系统深浅。
3. **补齐写作闭环的三件保命设施**——自动保存、历史快照、一键导出 PDF，让"不丢稿、能交付"成立。
