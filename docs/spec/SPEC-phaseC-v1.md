## 1. 产品定义

- **一句话描述**：Inkmark 是一款 macOS 个人轻量级 Markdown 写作应用，Phase C 把默认编辑形态从「源码 + 预览分栏」升级为「即时渲染的单栏写作面」。
- **目标用户**：单人写作者（本项目作者本人），日常写笔记、长文、技术文档。
- **核心问题**：Markdown 的标记符在写作时是噪音；分栏对照会强迫用户在「写」和「看」之间反复切换视线。写作工具应当让文字本身成为主角。

## 3. 明确不做（Out-of-Scope —— 锁定）

> 开发中如有人提出以下功能，**直接拒绝**，走变更流程。

| 不做的功能 | 原因 | 何时考虑 |
|------------|------|----------|
| Git 集成 | 个人场景 ROI 不足，历史快照已覆盖「找回旧稿」的真实需求 | 有版本协作需求时 |
| 文件树 / 目录浏览器 | 用户自述个人场景不需要；保留「打开文件夹」对话框即可 | 无计划 |
| 多标签页 | 单文件够用，多标签会引入「未保存状态管理」的复杂度 | 用户提出时 |
| 全局搜索 | 单文件 Ctrl+F 已够 | 无计划 |
| 属性 / 待办 / 检查面板 | 个人不需要，属企业级文档平台形态 | 无计划 |
| Mermaid / KaTeX | 渲染成本高，与「轻量」定位冲突 | v2 |
| WYSIWYG 表格编辑 | CM6 跨行替换被插件 API 禁止（见架构 §3.8），实现代价远超收益 | 表格保持源码常显 |

| 打字机模式（光标垂直居中） | 与专注模式的边界重叠，本期不做 | 无计划 |
| 页眉页脚开关 UI | MVP 不做配置项，默认开启 | v1.1 |
| PDF 导出在 Windows / Linux 上的原生实现 | 本机无法验证，且项目第一形态是 macOS | 有实际用户需求时 |

## 5. 设计 Token（锁定）

- **主色**：浅色 `#4F46E5` / 深色 `#6E76F0` / 纸感 `#9D5A2F`
- **深色主题关键约束**：`--accent-on` 为墨字 `#0B0C10`（对 `#6E76F0` = 5.13:1）；**白字压强调色仅 3.81:1 不达标，禁止使用**
- **字体**：浅/深 = `-apple-system` 栈；纸感 = Georgia → Songti SC / Noto Serif SC 衬线栈
- **图标库**：lucide-static@1.48.0（ADR-001），新增 24 个图标，尺寸 16 / 20 / 24px
- **正文行宽**：常规 46rem（现状延用）；阅读态与纸感 48~50rem
- **主题解析规则**：`<html data-theme>` **永远存已解析的具体值**（`light|dark|paper`），从不存 `system`；「跟随系统」由 JS 解析后写入；CSS 侧不写 `prefers-color-scheme` 分支
- **优先级**：用户手动覆盖 > 跟随系统

## 7. 边界与约束

- **平台**：第一形态 macOS；Windows / Linux 未验证，PDF 走降级
- **导出坐标映射（已实测，勿自行换算）**：WebKit `createPDFWithConfiguration` 对本项目导出 HTML 的映射是 **1 CSS px = 1 pt**。故 `exporters.js:69` 的正文 `font-size:15px` 在 PDF 中即为 **15pt**（不是 11.25pt）。反推依据：探针内容高 11844px 切出 15 页 A4（11844 ÷ 842 = 14.07 → 15）；若按 0.75 换算只会有 11 页。**任何"px → pt 乘 0.75"的换算都是错的。**
- **PDF 主题映射**：`light → light`、`paper → paper`、`dark → 强制 light`。PDF 是交付/存档/打印产物，不产出深底浅字的版本；这是「映射」而非「跟随」
- **PDF 排版密度**：A4 可用宽 467pt，15pt 正文下约 31 个中文字/行——此为正常密度（中文书籍常见 28~40 字/行），**不得**为追求行数而调小正文字号
- **PDF 页眉页脚**：恒为 **9pt** 绝对值（正文 0.6×），不引入比例换算
- **PDF 页面几何（已裁决，勿再读成两种）**：页高 842 = 上边距 64 + **正文 714** + 下边距 64；正文宽 **467pt**；页眉/页脚各 24pt 是**边距内的可用带宽上限，不参与相加**；页眉基线距页顶 58pt（正文上沿上方 6pt），页脚基线距页顶 786pt（正文下沿下方 8pt）；分页带 = **714pt**
- **PDF 版式宽**：导出正文容器宽 = **467px**（覆盖 `exporters.js` 的 `max-width:46rem`），HTML 导出保持 46rem；两份产物共用同一模板、仅版式宽参数不同，**禁止用 `transform: scale` 凑宽度**（会破坏 1px=1pt 的分页假设）
- **导出 HTML 硬约束**：根元素**禁止**使用 `zoom` / `transform: scale` —— 分页依赖 CSS px 与 PDF pt 的 1:1 假设，缩放会破坏页数计算（ADR-003 §Consequences-6）
- **页数上限**：单次导出硬上限 500 页，防超长文档失控
- **响应式**：窗口最小宽度以下工具条按阈值从右往左折叠进「更多」菜单，**不横向滚动**
- **无障碍**：可交互元素键盘可达；分割条已支持方向键
- **性能目标**：编辑输入无可感延迟；15 页 PDF 导出 < 2s（探针实测 1.11s）

## 8. 内嵌已知坑（从项目记忆拉取，实施前必读）

| # | 坑 | 技术栈指纹 | 根因 | 修法 |
|---|----|------------|------|------|
| 1 | `<style scoped>` 里写 `:global(prefix) 后代` | vue@3.5 | 编译器把选择器拍平成只剩前缀，导致 body 被涂色 / 整窗点不动 | 组件内用自有 class；真全局规则放非 scoped 块 |
| 2 | 用 `update.scrollChanged` 监听滚动 | @codemirror/view | `ViewUpdate` 无该属性，条件恒假 | 用原生 `view.scrollDOM.addEventListener('scroll')` |
| 3 | 用 `-webkit-app-region` 拖窗口 | wails@v2 | WKWebView 不认，Wails 用自有属性 | 用 `--wails-draggable: drag / no-drag` |
| 4 | 浏览器预览整页白屏 | wails@v2 | `EventsOn` 读 `window.runtime`，浏览器下 undefined 且炸在 setup | 包 `safeEventsOn` 守卫 |
| 5 | 设置 `options.Menu` 后 ⌘C/⌘V 失效 | wails@v2 | 自定义菜单整体替换默认菜单 | 手动拼回 `menu.EditMenu()` 等；`AppMenu()` 必须排第一 |
| 6 | `vite build` 删掉 `dist/.gitkeep` | vite@6 | 构建清空 dist | 每次构建后 `git checkout -- frontend/dist/.gitkeep`，**不要提交该删除** |
| 7 | 双向滚动联动「慢慢上滑」 | 自定义 | scroll 事件派发晚于 rAF，帧锁失效；映射不可逆时循环放大 | 记录写入值做回声识别，`scrollTop ≈ 写入值` 即忽略 |
| 8 | 改 token 后导出 HTML 配色不一致 | 本项目 | `exporters.js` 是**第二份样式源**（自包含，不 import token） | 改 token 必须同步 `exporters.js`，纳入 review 清单 |
| 9 | `bash grep` 的 `\|` 交替假阴性 | 本机环境 | 工具链缺陷 | 校验文本存在性**一律用 ripgrep** |
| 10 | 同文件多处并行 Edit 丢补丁 | 本机环境 | 实测随机丢补丁且无报错 | 同一文件的多个 Edit **串行**执行，改完跑构建核对 |
| 11 | CM6 插件装饰两条禁令 | @codemirror/view 6.43.13 | 插件装饰不得 block、不得跨行替换 | 一律**行内替换**；表格等跨行结构不做 WYSIWYG |
| 12 | 按 `package.json` 的 `^6.38.0` 查 API | @codemirror/view | 声明范围 ≠ 实际锁定版本 | 查 `node_modules/<pkg>/package.json` 的 `version` |
| 13 | Wails 打印必然弹面板 | wails@v2.16.0 | `Application.m:492` 的 `showsPrintPanel = YES` 硬编码 | 不走 Wails 打印通路；走 ADR-003 路线 A′ |
