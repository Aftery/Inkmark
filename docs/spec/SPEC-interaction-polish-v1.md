## 1. 表格交互

### 1.1 对齐（可视化）

- 操作条上三档按钮（左/中/右），作用于**活动列**（最后一次获得焦点的单元格所在列）。
- 当前档位用 `aria-pressed` + accent 反色标示；按钮字形相同（`≡`），靠文字落位表达语义
  —— **零新增图标**（ADR-001 图标白名单 / P0-1 零 emoji 均不破）。
- 硬约束：**对齐只存在于 GFM 分隔行**（`:---:`）。故改对齐必须重建 `delimRaw` 并写回文档，
  只改内存 `aligns` 会在下次重渲染时静默丢失（`tableOps.rebuildDelim`）。

### 1.2 行列拖拽重排

- 表头列手柄 / 表体行手柄，鼠标进入表格才显形（`.is-hover`）。
- 落点用「指针在目标元素前半段 → 插到它之前」的通行口径（`dropIndexAt`）。
- **移动语义而非交换**：`moveColumn/moveRow` 是「抽出再插入」。交换会让「拖一下顺序全乱」。
- 松手才写文档：拖拽过程几十次 `pointermove`，每次都写会产生上百条撤销记录。
- 拖拽全程可用 `Esc` 取消。

### 1.3 结构变更后必须自己重建 DOM（本轮最隐蔽的坑）

`TableWidget.eq()` 在单元格编辑期间返回 `true`，CM 因此**复用旧 DOM**。增删行列 / 重排 /
改对齐之后文档已变、DOM 却还是老结构 —— 用户看到「点了按钮没反应」，一离开再回来才对。

修法：结构类操作一律走 `rebuild()`（按 model 重建 `<table>`，按行列下标还原焦点）。
这条已写进 `tableWidget.js` 文件头，避免后人当成可随意删掉的「多余代码」。

### 1.4 Tab / Enter 的既有一处越界缺陷

原实现在 `stepCell` 返回 false 时**无条件** `appendRow`：首格按 `Shift+Tab` 会「退不出去反而
多一行」。现改为只有正向越界才补行。

## 2. 智能输入

### 2.1 成对补全（`smartPair`，默认开）

覆盖 `* _ ` [ ( " '`（含全角 `（）` 与直角引号）。三条 Markdown 专属守卫：

| 守卫 | 理由 |
|---|---|
| 行首裸 `*` 不配对 | 那是列表标记；配对后按空格会写出 `* \|*` |
| 词内 `_` / `'` 不配对 | `snake_case` 与 `don't`；CommonMark 的 intraword emphasis 对 `_` 本就关闭 |
| 代码上下文一律不干预 | `arr[0]` / `a * b` 的正经输入不该被打断 |

另有三条通用能力：**越过**（光标后已是配对的闭合符时只移动光标，避免 `**粗体***`）、
**选区包裹**（有选区时包起来而不是替换掉）、**成对退格**（`\|` 夹在空配对中间时一次删两侧）。

三连反引号在行首展开为围栏代码块，光标落在块内空行。

### 2.2 智能标点（`smartPunct`，默认**关**）

- 三档：`off` / `curly`（“”）/ `corner`（「」）。**引号形态是排版偏好**，只给「开/关」
  等于替用户决定形态，故做成三档。
- 全角化只在**中文语境**生效（插入点前一个非空白字符是 CJK）；ASCII 语境一律不动，
  否则 `Hello, world` 会被改成全角逗号。
- 引号用**就近配平**而不是奇偶交替：交替在「删掉一半引号」后整体反相，是该功能最经典的 bug。
- 代码上下文不生效（与配对同一条 `inCode` 判定）。

### 2.3 选区 + URL → 链接

`[选中文字](url)`。**不能复用** `@codemirror/lang-markdown` 的 `pasteURLAsLink`：那条挂在
DOM 的 `paste` 事件上，而 `⌘V` 已被全局分发 `preventDefault`（第十四轮根因），它在本仓
永远不会触发。故实现落在粘贴命令执行体里。

## 3. 键位与微操

### 3.1 标题：⌘1~⌘6 定级，⌘⌥↑ / ⌘⌥↓ 逐级升降，⌘⌥0 正文

- **为什么是 ⌘1~⌘6**：Typora 惯例，也是用户明确要求。`⌘1~⌘3` 原归视图三态，该三态随阅读态
  于 2026-10-14 整体移除，键位自那以后空置，无冲突。
- **为什么正文档是 ⌘⌥0 而不是 ⌘0**：`⌘0` 是「重置缩放」的既有契约（README 已写、状态栏可点击
  循环），抢它会破坏肌肉记忆与门禁口径。
- **为什么升降不是 ⌘+ / ⌘-**：同上，`⌘=` / `⌘-` 是视图缩放。用户要的「改变字号」由缩放承担，
  逐级升降只动**标题级别**，两者正交。
- **阶梯**：正文(0) → h6 → h5 → … → h1，两端 clamp **不循环**。循环会让 h1 再按「升级」跳到
  正文 —— 用户按了「变大」却看见字变小，是这条交互最容易被骂的形态。

### 3.2 列表：Tab / Shift+Tab 缩进 + 自动重编号

- 缩进统一 +2 空格（Markdown 列表嵌套通行单位）。
- 反缩进**吸附到父级缩进**，不是无脑删 2 空格：用户手写 3/4 空格时也能一次回到父级；
  4 空格缩进在列表里会撞上「缩进代码块」的边界，这是 CommonMark 的真陷阱。
- 重编号同时处理**新旧两个层级**：缩进会把一行从旧组摘走，旧组剩下的成员不重排就会留下
  `1. 3.`（渲染仍是 1、2，源码却写着 3）。
- **首项规则**：组首行未被改动时保留其显式起始号（用户写 `3.` 开头是有意义的，CommonMark
  渲染 `start=3`），只有它本身被改动（成为新组开头）时才从 1 起。
- 非列表行一律返回「不处理」，交回 `indentWithTab` —— 代码块里的 Tab 必须仍是插入缩进。

### 3.3 keymap 顺序是一条**静默失效**契约

CM 的 keymap 按扩展**声明顺序**决定优先级。`listIndentExtension()` 必须写在含
`indentWithTab` 的那个 `keymap.of([...])` **之前**，否则 Tab 永远轮不到列表缩进，
而且不报错。这条已由 `editor-wiring.test.mjs` 机检（含锚点存在性断言，防判据失效假绿）。
