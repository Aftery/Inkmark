## 1. 视图三态切换

### 1.1 入口

- **唯一入口：系统菜单「视图」**，三个选项为 **Radio 组**（单选勾选态），置于「切换主题」之前：
  ```
  视图
  ├── 编辑模式        ⌘1
  ├── 预览模式        ⌘2
  ├── 双栏模式        ⌘3
  ├── （分隔线）
  ├── 专注模式        ⌘⇧F        ← §2
  ├── （分隔线）
  ├── 显示/隐藏大纲    ⌘⌥O       ← §3
  └── 切换主题        ⌘⇧L        ← 现状保留（main.go:84）
  ```
- Wails v2.16 的 `pkg/menu` 已提供 `AddRadio` / `AddCheckbox`（`~/go/pkg/mod/.../wails/v2@v2.16.0/pkg/menu/menu.go:31,38`），菜单侧单选态可表达。但**勾选态如何随前端状态回写**是实现难点（见开放问题 2）。
- **不设前端 UI 入口**：顶栏保持现标题栏形态（`App.vue:325-327`），不加按钮——操作全在系统菜单栏是本项目既定纪律（README 设计要点 6）。

### 1.2 三态定义与各区域表现

| 区域 | 编辑态（⌘1） | 预览态（⌘2） | 双栏态（⌘3） |
|---|---|---|---|
| 编辑区 `.editor-pane` | 独占全部宽度 | 隐藏 | 按 `editorWidth` 百分比（现状 `App.vue:337`） |
| 预览区 `.preview-pane` | 隐藏 | 独占全部宽度 | 占剩余宽度（现状） |
| 分割条 `.divider` | 隐藏 | 隐藏 | 显示，可拖（20%~80% 不变，`App.vue:282-283`） |
| 侧栏（文件/大纲） | 不受影响 | 不受影响 | 不受影响 |
| 顶栏 | 保留（标题 + 脏标记） | 保留 | 保留 |
| 滚动联动 | 停用 | 停用 | 生效（锚点映射 + 互斥锁不变） |
| 分栏宽度记忆 | 保留值，不销毁 | 保留值，不销毁 | 生效（`App.vue:286-287`） |

### 1.3 默认态与持久化

- **默认：双栏态**（与现状一致，首次启动不变脸）。
- 视图态写入 `localStorage`（key 建议 `inkmark-view-mode`），重启恢复上次态。细节见开放问题 1。

### 1.4 边缘约束（给架构师/实现的硬性口径）

1. **三态切换必须保 DOM 存活**（隐藏用 `v-show` / CSS，不用 `v-if`）：CodeMirror 实例、预览 DOM、锚点缓存（`anchorsCache`，`App.vue:90`）都不应因切态销毁重建——否则滚动联动与锚点映射会静默失效（README 设计要点 4 的三个坑会重新踩一遍）。
2. **打印导出不受当前态影响**：`@media print`（`App.vue:444-449`）只输出预览区。若用户在编辑态导出 PDF，打印样式必须强制恢复预览区显示，否则导出空白。此为硬验收项。
3. **滚动监听守卫**：单栏态下 `onEditorScroll` / `onPreviewScroll`（`App.vue:158-186`）需按可见性短路，避免隐藏面板产生无效映射。
4. 窗口最小宽 800px（`main.go:26`）不变；≤768px 回退标签切换属方案 A 响应式预留，本次不做。

## 2. 专注模式

### 2.1 与三态的关系：叠加态，不是第四态

- 专注模式是**叠加在当前视图态之上的沉浸开关**，不改变「编辑 / 预览 / 双栏」的排布语义。
- **进入时若当前不是编辑态，自动切到编辑态并记住原态；退出时恢复原态。**
  - 理由：专注 = 只和文字相处。双栏/预览态下「专注」无意义（预览区仍在视野里分心）；而「专注（双栏）」这种组合会让用户面对两套状态的心智负担。Typora 的打字机/专注也只在编辑语境里生效。
  - 此决策可调，见开放问题 3。

### 2.2 进入与退出

| 方式 | 说明 |
|---|---|
| 菜单「视图 → 专注模式」（Checkbox 勾选态） | 事件 `menu:toggle-focus`，与现有事件管道一致 |
| 快捷键 ⌘⇧F | 菜单 accelerator 承担（前端不重复监听，`App.vue:265-266` 的理由适用） |
| Esc | **前端 keydown 监听**。Esc 不在菜单 accelerator 里，不存在「菜单先消费按键」的冲突；监听器须排除 IME 组合中态（`event.isComposing`） |

- 进入专注时给一次性的轻提示（Toast，`--surface` 底 + `--meta` 字）：「已进入专注模式，Esc 退出」，3 秒自动消失，仅首次显示（localStorage 记忆已提示过）。
- 退出后焦点（focus）必须回到编辑器，光标位置不移动。

### 2.3 隐藏什么、显示什么

| 元素 | 专注模式下 | 备注 |
|---|---|---|
| 顶栏（标题/脏标记） | **隐藏**（整条 44px 让给内容） | macOS 红绿灯为系统绘制不受影响；隐藏后窗口仍可从内容区顶部边缘拖动？——不，允许失去拖拽区，专注时就是要全给内容 |
| 侧栏（文件/大纲） | **隐藏** | 常驻可见性状态另行记忆，退出专注恢复 |
| 语法标记（`##`、`**` 等） | **保持原样，不隐藏不淡化** | 本编辑器是源码模式而非 Typora 的所见即所得；淡化标记需按 token 粒度做 CM decoration，成本与收益不成比例。**本次明确不做**（记录为将来可选） |
| 滚动联动/分割条 | 编辑态下本就不可见 | 不涉及 |
| 正文段落 | **光标所在段落块全亮，其余段落淡化** | 见 §2.4 |

### 2.4 光标所在段落的处理（核心交互）

- **段落块定义**：连续非空行构成的块（与 CommonMark 段落直觉一致；列表连续项视为一个块）。
- **淡化规则**：
  - 非活动段落块：`opacity: 0.4`（作用于 `--fg` 文本之上，不引入新颜色——alpha 变体符合「组件禁裸 hex」纪律）。
  - 活动段落块：`opacity: 1`，且光标本就以 `--accent` 着色（现状），强调色用量仍满足每屏 ≤2 处。
  - 过渡：`opacity` 变化 160ms、`--ease-standard`，尊重 `prefers-reduced-motion`（reduce 时归零延迟）。
  - 每屏强调色占用：光标 1 处，不新增。
- **活动块随光标实时切换**：光标移动（含点击、方向键、滚轮不切、仅光标动才切）→ 新活动块亮起、旧块淡出。
- **淡化只是视觉层**（CM6 decoration / theme 层实现），不改变文档内容、选区与编辑能力——被淡化的段落照常可点击进入并立刻变为活动块。
- **不做**：打字机居中滚动（Typora 的 typewriter mode）、非活动段落点击后延迟切换。均为超出范围的克制，见开放问题 8。

### 2.5 验收口径（交互侧）

- ⌘⇧F 在任何视图态下都能进入；Esc / ⌘⇧F 都能退出且退出后视图态与侧栏可见性还原。
- 进入专注后除活动段落与光标外无任何 UI 元素可见（顶栏、侧栏、菜单条除外——系统菜单栏属 macOS 全局）。
- 淡化不影响选中文本、查找、编辑操作的可用性。
- 暗色主题下淡化段落在 `#1F1F1E` 画布上仍可辨认（对比退化可接受，因文字仍可交互）。

## 3. 大纲

### 3.1 位置：侧栏第二个 tab

- 侧栏改为**双 tab：文件 / 大纲**，tab 栏置于现有 `.sidebar-title`（`App.vue:332`）之下或替代之，高度沿用 `--toolbar-height` 内的行内 tab（文字标签，不用图标——零新增图标几何，符合 ADR-001 白名单纪律；若用户想要图标，从 `lucide-static@1.48.0` 登记 `list` 几何即可，仍走 `paths.js` 白名单）。
- **侧栏存在性重构**：从「打开文件夹才出现」（`App.vue:331` `v-if="folderPath"`）改为「**可随时开关的常驻面板**」：
  - 未打开文件夹时，「文件」tab 显示空态引导文案 + 「打开文件夹」CTA（DESIGN §8 五态覆盖的 Empty 态）；
  - 「大纲」tab 无文件夹也始终可用（大纲来自当前文档，与文件夹无关）。
  - 此改动需要用户确认，见开放问题 5。
- 不采用独立右面板：三栏 + 两条分割条的复杂度超出「安静纸面」的气质，且与双栏拖拽逻辑（`App.vue:295-305` 的宽度百分比按「去掉侧栏后的可用宽」计算）叠加后状态空间爆炸。

### 3.2 层级展示

- 数据源：**编辑器文档的标题行扫描**（复用 `App.vue:100-118` 的状态机：跳过 ``` / ~~~ 围栏内 `#`），不用预览 AST——编辑态下预览不存在，源码扫描在三种视图态下都可用。
- 数据更新：`onDocChange` 的 nextTick 时机（`App.vue:75-77`，锚点失效处）同步标记大纲失效，惰性重建。
- 展示规则：
  - h1–h6 全部显示，按层级缩进（每级 16px，4px 网格）；
  - 标题文本去掉 `#` 标记并折叠连续空格，超长省略号截断（Edge 态）；
  - 无标题文档显示空态引导：「当前文档没有标题，用 # 开始一节」。
- 视觉：文字用 `--fg-2`，hover 底 `--surface-2`；**当前节高亮**用 `--fg` + `--weight-emphasize` + 左缘 2px `--accent` 竖条（与 restyle-plan §4.2 备选方案 B 同一视觉语言，不新造样式）。每屏 accent 占用：竖条 + 编辑区光标 = 2 处，达标。

### 3.3 点击跳转

- 点击大纲项 → 编辑器 `scrollDOM` 滚到对应标题行顶（标题行 `coordsAtPos` 定位，标题贴近视口顶部留 `--space-4` 呼吸）。
- 双栏态下预览区经现有滚动联动跟随（`App.vue:158-171`），无需单独实现预览跳转。
- 键盘可达：大纲列表可 Tab 进入，↑/↓ 在项间移动，Enter 执行跳转；当前项有 `:focus-visible` + `--focus-ring`（DESIGN §8）。

### 3.4 滚动同步高亮

- 以编辑器滚动位置为驱动：利用现有锚点序列（`App.vue:148-156` `mapByAnchors` 的区间定位思路）反查「当前视口顶部所处标题区间」，将该标题在大纲中置为当前项，并 `scrollIntoView({ block: 'nearest' })` 保持可见。
- 预览态下编辑器隐藏：以预览滚动位置经同一映射反查（预览侧锚点 `App.vue:121-131` 已有）。
- 防抖：滚动驱动的高亮更新用 `requestAnimationFrame` 节流即可（与互斥锁同量级），不引入额外库。

### 3.5 快捷键

- **⌘⌥O**：切换侧栏显示并聚焦大纲 tab（若侧栏隐藏则展开；若已在大纲 tab 则整体收起侧栏）。
- 避开 ⌘⇧O（打开文件夹，`main.go:71`）。备选方案见开放问题 6。

## 5. 视觉与 Token 合规清单

1. 本方案**零新增颜色**：淡化用 opacity、当前项用 `--fg`/`--fg-2`/`--surface-2`、竖条与光标用 `--accent`、边线用 `--border`/`--border-soft`。
2. **零新增图标**（推荐口径）：tab 用文字标签；若用户要图标，只从 `lucide-static@1.48.0` 登记（如 `list`），仍经 `AppIcon.vue` + `paths.js`，禁止裸 svg / emoji。
3. 圆角 ≤12px；侧栏/列表容器零阴影；动效 120–240ms 且尊重 `prefers-reduced-motion`。
4. tab、大纲列表、专注 Toast 的间距全部落在 4px 网格。
5. 触控目标 ≥44×44px（tab 行高、大纲行高按此约束）。

## 6. 开放问题（需用户/团队拍板）

1. **视图态持久化**：是否接受「重启恢复上次视图态」（推荐：是，key `inkmark-view-mode`）？还是每次启动固定双栏态？
2. **菜单勾选态回写**：Wails v2 `AddRadio` 的 checked 值要随前端状态更新，需经 Go 侧重建/更新菜单（`runtime.MenuSetApplicationMenu` 一类调用）。是否值得为勾选态引入「前端 → Go → 菜单」的反向通道？还是接受菜单项无勾选态（靠前端状态 + 行为正确性保证）？——需架构师评估成本后定。
3. **专注模式进入时自动切到编辑态、退出恢复原态**（§2.1）：确认这一策略，还是希望专注模式对当前视图态完全透明（双栏下也只淡化不动布局）？
4. **段落淡化强度**：`opacity: 0.4` 是否合适（Typora 观感约 0.3–0.5 区间）；标题行是否与普通段落同等对待（推荐：同等对待，不额外保留标题常亮）。
5. **侧栏常驻化**：侧栏从「打开文件夹才出现」改为可随时开关的双 tab 面板（§3.1），是结构性变更，需用户确认。
6. **大纲快捷键**：⌘⌥O 是否可接受？备选：⌘⇧E、⌘8。
7. **大纲默认展开层级**：h1–h6 全量平铺展示（推荐，配合缩进），还是提供层级折叠（折叠交互会引入 chevron 图标与额外状态）？
8. **打字机居中滚动**：专注模式下是否连带做「光标行保持屏幕中部」（Typora typewriter mode）？推荐本次不做，保持克制。
9. **专注模式首启提示**：Toast「Esc 退出」只提示一次（推荐）还是每次进入都提示？

## 7. 本次不做（out-of-scope）

1. 不做所见即所得 / 语法标记隐藏（源码模式形态不变）。
2. 不做打字机居中滚动、打字机音效等超范围专注增强。
3. 不做大纲拖拽排序、大纲备注（Bear 式）。
4. 不做≤768px 的移动式回退布局（方案 A 已预留，另行迭代）。
5. 不改导出模板、不动 Go 端 IPC 契约（新增的只是菜单 emit 事件，与 `app.go` 无关）。
