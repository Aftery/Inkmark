## 1. 标记显隐规则（核心交互）

### 1.1 显隐粒度：按块（block）reveal，不按行

- **块的定义沿用方案 B §2.4**：以空行/文档边界分隔的连续非空行构成的块；列表的连续项、引用的连续行、围栏代码块整体各视为一个块（复用 `paragraphRange` 思路，`createEditor.js:62-70`，需按块语法扩展）。
- **规则**：光标（含选区）所在块 → 该块内所有源码标记原样浮现（`##`、`**`、`-`、`> `、`` ` ``、`[]()` 全部可见可编辑）；其余块 → 源码标记隐藏，显示渲染效果。
- **为什么按块不按行**：
  1. 标记多数跨行存在（引用块每行的 `>`、列表项、多行段落中的加粗），按行 reveal 会出现「同一句话一半带星号一半不带」的破碎观感；
  2. 与方案 B 专注模式的「活动段落块」概念天然对齐，两个Decoration 系统共用一套块判定，心智与实现都收敛；
  3. Typora 实际行为即块级 reveal。
- **例外——围栏代码块**：代码块内的内容永远按代码显示（`--font-mono` + `--hl-*` 高亮，现状已如此），围栏标记 ```` ``` ```` 只在光标进入代码块时浮现。

### 1.2 逐元素显示规则（WYSIWYG 态）

| 元素 | 光标外（非活动块） | 光标内（活动块） | 备注 |
|---|---|---|---|
| ATX 标题 `#`~`######` | 隐藏 `#` 与空格，显示大字号标题（mdHighlight 现状字号阶梯） | `#` 浮现，字号保持 | 隐藏 `#` 后文本左移，属预期行为（Typora 一致） |
| 段落加粗 `**x**` / 斜体 `*x*` / 删除线 `~~x~~` | 隐藏包裹标记，内容按字重/斜体/删除线渲染（现状 strong 510 / emphasis italic 已有） | 标记浮现 | 成对标记必须整体显隐，禁止只显示半边 |
| 行内代码 `` `x` `` | 隐藏反引号，内容按 `--font-mono` + `--code-inline-bg` 渲染 | 反引号浮现 | 背景色与预览区 `.preview-body code` 一致（§3） |
| 围栏代码块 ```` ``` ```` | 隐藏首尾围栏行标记，语言标记符随围栏隐藏；语言名（`js` 等）在非活动时淡化为 `--meta` 弱显示于块右上或行首 | 围栏行恢复为普通文本行 | 语言名弱显示是 Typora 同款行为；高亮配色沿用现状 |
| 链接 `[text](url)` | 隐藏 `[` `]` `(url)`，仅显示 text，着 `--accent` + 下划线（现状 t.link 已有） | 全部源码浮现 | url 过长时活动态原样显示（源码模式心智）；不截断 |
| 图片 `![alt](src)` | 整体替换为图片 widget（`Decoration.replace` + widget 渲染 `<img>`，alt 为空时显示占位框 + 文件名弱文本） | 源码浮现 | 样式沿用 `.preview-body img`（max-width 100%、radius-sm） |
| 无序列表 `-` / `*` / `+` | 隐藏源标记，以渲染 bullet（`--muted` 色 marker）替代 | 源标记浮现 | 缩进层级保持源码缩进语义 |
| 有序列表 `1.` | 隐藏源标记，以渲染序号替代 | 源标记浮现 | 序号按实际顺序渲染，与源码数字可能不同（如手写 `3.` 开头）——按 CommonMark 实际序号显示 |
| 任务列表 `[ ]` / `[x]` | 替换为真实 checkbox widget（`accent-color: var(--accent)`，预览现状同款）；勾选态整项弱化（`.preview-body li:checked` 同款：`--muted` + line-through） | 源码 `[ ]` 浮现 | 点击 widget 可切换（§6.3） |
| 引用块 `>` | 隐藏每行行首 `> `，整块套用预览同款样式（`--surface-warm` 底、`--fg-2` 字、radius-sm） | `>` 浮现，底色样式保持 | 嵌套引用逐级缩进 |
| 水平线 `---` | 渲染为 1px `--border` 分隔线（可加 widget 或仅依赖现状主题样式） | 源码浮现 | |
| 表格 | **v1 保持源码常显**（不做表格 WYSIWYG），仅套用预览同款表格样式（发丝边框） | 不区分 | 纯 Decoration 无法把管道表格重排为真表格；列为开放问题 2 |
| 空行 | 无标记，正常空行 | 无变化 | 见 §1.4 光标在空行时的规则 |
| 转义 `\[` 等 | 永不隐藏转义符 | 不区分 | 隐藏会让用户误以为字面量丢失 |

### 1.3 选区跨越多块

- 选区（含双击选词后拖选、⌘A 全选）触及的所有块，一律按**活动块**处理：标记全部浮现。
- 理由：选区意味着用户正在「看源码做编辑」，隐藏标记会让选中的渲染文本与剪贴板内容（源码）对不上，复制/剪切出错误预期。
- 光标折叠回单块后，恢复常规规则。

### 1.4 显隐时机

| 场景 | 行为 |
|---|---|
| 光标移入块（点击/方向键/⌘F 定位/大纲跳转） | 该块标记**立即浮现**，无延迟 |
| 光标移出块 | 该块标记**立即隐藏**，无延迟 |
| 光标停在空行 | 该空行块无标记可言；前后块均隐藏（光标不属于任何内容块） |
| 打字过程中 | 光标所在块始终是活动块，标记全程可见，**不存在打字时标记闪烁** |
| 滚动（不移动光标） | 活动块不因滚出视口而改变显隐；Decoration 只作用于 `visibleRanges`，滚回时状态一致 |
| 撤销/重做（⌘Z） | 跟随光标落点重算，规则不变 |
| 程序性 dispatch（大纲跳转、打开文件） | 同点击：落点块立即激活 |

- **明确不引入隐藏延迟**（如「移出 300ms 后才隐藏」）：延迟制造「半显半隐」的中间态，与「安静纸面」气质相悖；Typora 亦为立即切换。若实测光标在块边界快速往返造成闪烁，缓解手段是 §2 的过渡策略而非延迟。
- 打开文件 / 切换文档时，光标默认在文档起点：起点所在块为活动块，其余全渲染。

## 2. 视觉过渡

- **结论：标记浮现/隐藏不加动画，瞬时切换。**
- 理由：
  1. 隐藏 `##`/`**` 会改变行内文本流位置（文字左移），这是**布局变化**，opacity/transform 过渡都无法平滑表达，强行动画只会产生滑动噪感；
  2. 切换频率与光标移动同频，120ms 的过渡在连续移动光标时会变成永久闪烁；
  3. Typora 即无过渡，用户对此形态的心理预期已经建立。
- 唯二保留的过渡（均为既有 Token，非本方案新增）：
  - 专注模式段落淡化的 `opacity` 过渡（方案 B §2.4，160ms）——纯透明度、不改布局，可平滑；
  - 空标记的弱提示色（§6.1）如需淡入，≤120ms、`--ease-standard`、尊重 `prefers-reduced-motion`。
- DESIGN §7「过渡 120–240ms」条款在本方案的适用边界：**只约束不改布局的属性**（opacity/color），不约束标记显隐这类布局性切换。

## 3. 渲染样式体系（防分叉，方案 A 老坑的正式口径）

### 3.1 现状三层样式的盘点

| 层 | 位置 | WYSIWYG 态的角色 |
|---|---|---|
| mdHighlight（HighlightStyle） | `createEditor.js:17-52` | 已承担行内渲染：标题字号阶梯、strong/emphasis/strikethrough、行内代码字体、link 着色。标记隐藏后这些即「渲染效果」的主体，**基本无需改动** |
| preview.css | `themes/preview.css` | 块级渲染样式：blockquote 底色、pre/code 块、列表缩进与 marker、表格边框、img、任务列表弱化。当前选择器挂在 `.preview-body` 下，**编辑器用不到** |
| exportCss（内联静态拷贝） | `export/exporters.js:35-102` | 导出 HTML 的自包含样式，是 preview.css 的手工拷贝（注释自述「改动 Token 时同步这里」）——**这就是分叉点** |

### 3.2 目标架构：内容排版样式单一来源（设计口径，实现细节归架构师）

1. **抽取「内容排版层」**：把 preview.css 中描述「Markdown 渲染结果」的规则（标题/段落/行内元素/列表/引用/代码块/表格/hr/img/任务列表，即 §3.1 表第二行全部内容）沉淀为一份与容器无关的样式源（建议 `themes/content.css`，命名归架构师），选择器用语义类（如 `.md-content h1`），不绑定 `.preview-body`。
2. **两处消费，同一来源**：
   - 预览 DOM：`<div class="preview-body md-content">`；
   - 编辑器：CodeMirror 块级 widget（图片、任务列表 checkbox 等）与块级背景样式（引用块、代码块）通过同一 `.md-content` 类挂到对应 Decoration widget / line class 上。
3. **mdHighlight 与 content.css 的分工铁律**：行内文字属性（字号/字重/斜体/高亮色）以 mdHighlight 为准（CM 原生管线）；块级盒模型（margin/背景/边框/缩进/圆角）以 content.css 为准。**同一属性禁止两处同时声明**——这是比「两份文件」更隐蔽的分叉形态。
4. **导出模板的收敛路径**：exportCss 与 content.css 的关系从「手工同步」升级为「注释契约 + 人工核对清单」起步（低成本，本轮推荐），远期可选构建期生成（从 content.css 生成 exportCss 内联串）。是否本轮就做构建期生成，列开放问题 7。
5. **验收口径**：同一段 Markdown（含标题/引用/代码块/表格/任务列表）在编辑器非活动块、预览区（若保留）、导出 HTML 三处的观感一致；任何一处改样式必须能追溯到同一份源。

### 3.3 编辑器内的排版差异（有意保留）

- 编辑区正文列宽沿用 `--preview-measure`（46rem）限宽居中：编辑器 `.cm-content` 现状是全宽，WYSIWYG 态建议对齐预览的阅读行宽，使「编辑区即预览区」名副其实（列宽变化会牵动锚点等已退役逻辑，无历史包袱）。
- 行高/字号本就与预览一致（15px / 1.7），无需动作。
- `.cm-line` 的水平 padding（`--space-6`）与 content.css 的块级 margin 需在实现时合并校准，避免活动块浮现标记时块宽跳动——口径：**标记显隐导致的块内文本位移可接受，块级盒模型（外边距/底色范围）不得随显隐变化**。

## 5. 打印与导出口径（硬验收项）

### 5.1 原则：渲染管线与视图解耦

- 方案 C 取消的是**预览作为视图**，不取消**markdown-it 渲染作为管线**。`previewHtml`（`App.vue:24` computed）与预览 DOM（`App.vue:631-639`，v-html 常驻）继续存在，只是不再作为可见面板。
- **打印（⌘P → PDF）**：`@media print` 改为输出这个不可见的渲染 DOM（角色从「预览区」变为「打印层」）。现有硬验收「编辑态导出 PDF 非空白」的机制原样平移：打印层三态下保持渲染，`!important` 覆盖隐藏样式。需要改的只是被隐藏元素清单（分割条/侧栏/顶栏照旧隐藏，预览面板改为打印层常隐藏、打印时显示）。
- **导出 HTML（⌘⇧H）**：`buildHtmlDocument(title, previewHtml.value, theme)`（`App.vue:444-449`）输入就是渲染管线产物，**零改动**。
- 打印层不可见的具体形态（display:none 移出视口 / 宽高归零）归架构师，交互口径只有一条：**打印与导出的结果必须与用户在 WYSIWYG 态看到的渲染完全一致**。
- 风险继承：方案 B R1（编辑态下 v-html 持续全量渲染的性能）在 C 中从「隐患」变为「常态」——打印层永远在每次输入后重渲染。README 待办「渲染防抖」应随本方案从「可选优化」升格为「前置依赖」，写入实施前提（性能实现细节归架构师）。

### 5.2 验收口径

- WYSIWYG 态下 ⌘P 打印预览：所见内容与打印结果一致（标题字号、加粗、代码块配色、任务列表勾选态）。
- 源码态下 ⌘P：打印的仍是**渲染结果**，不是源码文本。
- ⌘⇧H 导出的 HTML 在浏览器独立打开，观感与编辑器一致（§3.2 第 5 条验收）。

## 6. 光标与编辑行为的特殊规则

### 6.1 空标记

| 情形 | 规则 |
|---|---|
| `****` / `____`（空加粗）、` `` `（空行内代码） | **永不隐藏**。空包裹标记没有「渲染结果」可显示，隐藏后用户找不到它 |
| `[]()`（空链接）、`![]()`（空图片） | 同上，源码常显 |
| `[text]()`（有 text 无 url） | 非活动块显示为普通 text 无着色；活动态可见 url 缺失 |
| 正在输入的未闭合标记 `**abc`（无右星号） | 无成对标记可隐藏，按普通文本显示；闭合瞬间起按渲染显示 |
| 刚清空内容的标记（`**x**` 删掉 x 变 `****`） | 立即回到「永不隐藏」态——显隐规则以**当前文档内容**实时判定，不记忆历史 |

- 空标记在非活动块中的弱提示：着 `--meta` 色（不新增颜色），提示「这里有个空标记待处理」。
- 空行/仅标记的行（如一行只有 `**`）构成单行块，光标进入即活动，无特殊逻辑。

### 6.2 点击行为总则

- **默认总则**：点击渲染结果 = 把光标放到对应源码位置并激活该块（标记浮现）。这是 WYSIWYG 的第一性交互，所有元素先满足此条。

| 元素 | 单击 | ⌘+单击 | 备注 |
|---|---|---|---|
| 加粗/斜体/行内代码/标题文本 | 光标落位 + 块激活 | 同左（纯文本无特殊行为） | |
| 链接（渲染态） | **不导航**，光标落到链接源码 `[` 处 + 块激活 | 在系统默认浏览器打开 url | 编辑器内误触导航是写作软件大忌；⌘+点击外开是否做，列开放问题 3（涉及 WebView 内开外链的 Wails 能力） |
| 图片（widget） | 块激活 + 源码浮现 | 建议同单击（预览大图不在本期范围） | widget 点击热区即整图 |
| 任务列表 checkbox（widget） | **切换勾选态**（改写源码 `[ ]` ↔ `[x]`，触发 docChange） | 同左 | 例外于总则：点击是操作不是定位。勾选后整项弱化样式同步（预览同款） |
| 引用块/代码块空白处 | 光标落到该行行首 + 块激活 | 同左 | |

### 6.3 键盘在渲染态的语义

- 方向键在隐藏标记上移动时按**源码位置**步进（CM 原生行为，Decoration 不改变 doc 位置），光标可能出现在「渲染上看不见字符」的缝隙（如 `**` 处）。接受此行为（Typora 同款），不做视觉跳点补偿。
- Home/End、⌘←/⌘→ 按源码行首尾（含隐藏标记），同理接受。
- 选区高亮覆盖隐藏标记区域：选区背景（现状 `--accent` 22% 混色）画在渲染文本上即可，无需展开标记。

### 6.4 IME 中文输入下的抖动规避（硬规则）

1. **组合中态（composing）冻结显隐**：IME 组合期间（`isComposing` / `update.view.composing`）不重算块活动性、不增删 Decoration——组合中文本频繁增删，若此刻标记显隐切换，文本流左右跳动会导致候选框错位与已上屏内容抖动。
2. 组合结束（compositionend）后的第一次 update 统一重算一次。
3. **打字全程活动块不变**：正常打字（非组合）时块活动性只随光标跨块才变化，单块内打字零 Decoration 重建——只要块判定正确，抖动在源头不存在。
4. 候选词浮窗定位由 WKWebView 原生处理，Decoration 不干预；验收时以中文输入法连续打一段 200 字含加粗的文本为抖动专项用例。

### 6.5 与专注模式淡化的叠加细节

- 非活动块同时承受「标记隐藏 + opacity 0.4」：验收标准是暗色主题下淡化后的渲染文本仍可辨认（方案 B §2.5 既有口径，渲染文本比源码更易辨认，风险降低）。
- 专注模式下点击淡化块 → 该块立即变为活动块（亮起 + 标记浮现），一次交互两个状态同时翻转，无中间态。

### 6.6 解析完备性的口径

- 行内解析以 CM 的 markdown 语言（`@codemirror/lang-markdown`，现状已启用）为准，不引入 markdown-it 第二解析源——两套解析器的显隐判定不一致会直接表现为「标记者色异常」，此为架构约束（细节归架构师），交互口径：**凡是该隐藏而没隐藏、不该隐藏而隐藏的标记都算 bug**，逐元素用例回归。
- setext 标题（`标题\n===`）：doc 层面 CM markdown 语言可识别，与 ATX 同规则处理；大纲扫描器（`outline.js`）若不支持 setext 属既有已知差异，不在本方案范围扩列。
