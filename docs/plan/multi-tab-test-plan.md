## 0. 本文的写法与纪律

### 0.1 两条铁律（本文的所有判据都受它约束）

1. **假绿灯教训**：构建通过 + 测试全绿 ≠ 功能对。本仓的失败模式大量是「不抛异常、只是不生效」。
   因此本文每条判据都要求断言打在**该路径特有的可观测差异**上；凡是只能写成「条数 / 计数 / 布尔」的判据，
   本文一律标注「判据不足，需补可观测差异」并给出替代写法。
2. **变异自证**：每条新判据都要配「造违规输入 → 确认报红 → 确认退出码非 0」的元测试（§6.4）。
   「不报红」必须区分三种成因：**等价变异 / 测试打错位置 / 真没守住**（HANDOFF §4 ㉒），不得一律当成通过。

### 0.2 术语

| 术语 | 定义 | 锚点 |
|------|------|------|
| 标签页（tab） | 一个文档会话的可视化载体 | 待实现 |
| **前端标签键** | 前端用来识别「这是同一个 tab」的**本地键**。**必须**与 Go 侧 `docKeyOf` 区分开（见 C-1） | 待实现 |
| **Go 侧 docKey** | `hex(sha1(filepath.Clean(absPath)))[:16]`。**只在 Go 侧派生**，用于快照目录寻址 | `snapshot.go:48-58` |
| 未落盘标签键 | 未落盘文档**没有路径**，必须用**独立命名空间**（如 `untitled:<uuid>`），不得与路径派生规则混用 | C-1 |
| 激活标签 | 当前显示在编辑器里的那个 tab | 待实现 |
| `DocSession` | 一个 tab 的内存态：path / EditorState / dirty / saveState | 架构方案给定 |
| 聚合脏（anyDirty） | 所有已打开 tab 中**任一**为脏 | ADR-005 §四要求 `OnBeforeClose` 遍历全部已打开文档 |
| **dirty（视觉）** | 内存 ≠ 磁盘。视觉须**克制**（低调小圆点），**不得**高对比白点 | team-lead 裁决 |
| **error（视觉）** | 自动保存失败 / 只读目录 / 未落盘新文档。**异常态**，必须与 dirty **明确可区分** | team-lead 裁决 |

### 0.3 「未验证」标注约定

本文严格区分三种状态，任何一条都不许混写：

- **【已验证】**：本轮真读过代码 / 真跑过命令，附「文件:行号」或命令输出。
- **【待实现后验证】**：判据已定好，但被测代码尚不存在（当前状态就是如此）。

#### C-1 同路径幂等是**架构约束**，不是可选 UX

依据：`snapshot.go:48-58` 的 `docKeyOf`（`hex(sha1(filepath.Clean(absPath)))[:16]`）
+ `ADR-005 §四` 的多文档升级路径（`docKey → dirty` 映射）。

- **同一路径开第二个标签会让 `docKey → dirty` 映射退化**（两个 tab 抢同一个键），
  从而破坏 ADR-005 的 dirty 单义不变量（`ADR-005:19`：dirty ⟺ 内存内容 ≠ 磁盘内容 —— 且必须是**那一份**内存内容）。
- 故「打开已打开文件 = 切到已有标签」**必须**写进验收标准（见 AC-03 / AC-04 / AC-56），
  不是「体验上更好」的可选项。
- **未落盘新文档没有路径**，其标签键**必须**用**独立命名空间**（如 `untitled:<uuid>`），
  **不得**与路径派生规则混用（见 AC-57 / AC-58）。
- 补充（QA 从 `snapshot.go` 读出的额外约束）：`docKeyOf` 的注释明确写
  「绑定层只收 absPath，**前端不实现 sha1 / 路径规则**（防止两端各算一份导致『写入目录 A、读取目录 B』的沉默不一致）」。
  因此前端的标签键**不是** Go 的 `docKey`，而是**另一套本地键**（AC-58）；
  前端若自行实现 sha1 派生，就是重演本仓记过多次的「两端各算一份 → 沉默不一致」。

#### C-2 键位唯一真源 = `frontend/src/composables/useShortcuts.js` 的 `COMMANDS` 表

- 原生菜单 2026-10-06 已下线（`main.go` 只剩平台化窗口配置），
  `scripts/verify/parse-main-menu.mjs` 如今解析的也是 `useShortcuts.js`（文件名是历史遗留）。
- `docs/architecture/ADR-004-keybinding-map.md` **已过时，不得依据**：
  状态仍是 `Proposed (2026-10-01)`，且其 Background 引用 `main.go:69-92` 的 `BuildMenu`
  —— 该函数已随原生菜单下线删除（见本文件头「不要依据的文档」）。
- 门禁 `scripts/verify/verify-shortcuts.mjs` 比对**表 / README 快捷键节 / 应用内速查表**三方，
  并检查表内撞键。新增标签相关命令**必须**三处同步（§6.3）。

### 2.1 产品决策点

#### D-1 后台 tab 是否自动保存 —— **待 team-lead 拍板**

> QA **不代替裁决**。以下把两个选项各自的**测试影响**写清楚，供拍板参考；
> QA 的倾向性意见单列，标注为「倾向」而非「决定」。

**选项 a：后台 tab 也自动保存**（每 tab 独立定时器，写盘单元绑定到该 tab）

| 维度 | 影响 |
|------|------|
| 产品 | 与「自动保存是常态、防丢稿」的定位一致（`useDocumentState.js:12-13`）；切走再切回之间的丢稿窗口仍是 800ms |
| 测试 | **必须**新增「后台 tab 触发写入 → path 与 content 都来自该 tab」的判据（AC-19）；**必须**新增「后台 tab 写盘期间用户在别处编辑 → 不得误判脏」的判据（AC-20/21）；测试面比选项 b 大 |
| 风险 | 若实现沿用现状的「路径读 `filePath.value`、内容读 `getEditor().state.doc`」两个独立来源（F-07），后台 tab 的定时器会**拿激活 tab 的内容写进后台 tab 的文件** —— 数据损坏、零报错（R-1） |
| 门禁 | 需要 M-7（写盘单元同源）与 M-8（写盘期间切 tab 不误判）两条元测试都报红 |

**选项 b：只保存激活 tab**（后台 tab 的脏一直留到切回来）

| 维度 | 影响 |
|------|------|
| 产品 | 更保守：不写用户没打算保存的中间态；但切走后若直接关窗，后台 tab 的内容只能靠**快照留底**（AC-37），不是自动保存 |
| 测试 | 判据更简单：「后台 tab **不得**发生任何写盘调用」（AC-19 改写）；不需要「后台 tab 写盘期间」的分支测试 |
| 风险 | 切走 → 关窗这条路径上，用户会看到「关窗弹确认」，而内容其实已被快照留底 —— 提示语与实际风险不完全对齐；快照间隔受 `prefs.snapshot` 影响（间隔为 0 时连快照都没有，`useDocumentState.js:162`），**存在「既没自动保存、也没快照」的窗口** |
| 门禁 | M-7 变成「后台 tab 不得写盘」方向；M-8 可简化 |

**QA 倾向**：倾向选项 a，理由是 b 存在「既没自动保存、也没快照」的丢稿窗口（见上表「风险」行），
而 a 的主要风险（错写盘）**可以用判据钉死**（M-7/M-8 + AC-18/19/20），不是只能靠人盯。
但**最终拍板权在 team-lead**。

**无论选哪个，AC-18（写盘单元同源）都必须成立** —— 这是 C-1 级别的架构约束，不是可选项。

#### D-2 关闭最后一个标签页后的行为 —— **产品结论已定（PM 2026-10-28），呈现形式待 team-lead 拍板**

> **PM 的产品结论**（2026-10-28 回传，原文）：**关闭最后一个标签后应用保持运行、显示空状态、不退出进程。**
> 空状态**只能**提供「新建文档」「打开文件」两个入口。

**已定（不可再议）**

- 应用**不得**退出进程（当前单文档实现的退出入口只有红绿灯 / 自绘 ×，本条与「关窗口」是两件事）。
- 关闭最后一个标签后**必须**呈现一个可继续工作的空状态。
- 空状态**必须**提供「新建文档」「打开文件」两个入口。

**待 team-lead 拍板：空状态的呈现形式**

| 形式 | 说明 | 代价 |
|------|------|------|
| (a) 保留一个未命名空标签 | 与现状零行为变更（现状「新建文档」得到一个 `filePath=''` 的空文档，`useFileOps.js:144-148`） | 标签栏里永远挂着一个「未命名」，与「全部关闭」的直觉略有出入 |
| (b) 独立空状态面板 | 零标签 + 一个专门的空状态视图 | 需新增分支：CM 要一个空 doc、`title` 要退化成「未命名」、`resetSession` 的调用点要新增；且**空状态面板不得成为「标签栏」的替代品** |

**QA 倾向：(a)** —— 与现状零行为变更、净增分支最少。
但**无论哪种形式，AC-77 的可观测要求都一样**：进程不退出 + 有那两个入口。
[注意] 空状态**不得**放「恢复上次打开的文档」—— 「最近打开」已整体下线（`README.md:321`；
`app.go:29-31` 只剩历史注释提及 `AddRecent` / `ClearRecents` / `loadRecents` / `saveRecents` / `recentLabels`，
函数体本身不存在）。除非 P5「恢复最近打开」同批做进来，否则那是个**点了没反应的入口**
（本仓反复吃过的「静默失效」形态）。

#### D-3 关闭标签后的激活落点 —— **待 team-lead 拍板**

PM（许清楚）基于竞品调研的建议：采用 Zed 的 `tabs.activate_on_close` 语义，
提供 **history / neighbour / left_neighbour** 三个选项，**默认 history**
（https://zed.dev/docs/reference/all-settings）。

> QA 倾向：采纳 PM 的建议 —— **默认 history**（激活「上一个访问过的标签」），
> 三个策略各自的行为**必须能独立验证**（至少默认项进回归集）。
>
> 理由：history 策略在「A、B、C → 关 B」时激活的是**上一个访问过的标签**（此处为 A），
> 比「总是右邻 / 总是左邻」更符合用户对「回到我刚才在的地方」的直觉，
> 也避免「关掉中间标签后焦点莫名其妙跳到末尾」的已知差评形态。
>
> 三个策略的判据差异（**逐条独立可验**，见 AC-28）：

| 策略 | A、B、C → 关 B 后的激活 | 判据写法 |
|------|------------------------|---------|
| `history`（默认） | 上一个访问过的标签（A） | 断言 `activeDocKey` 精确等于 A 的键 |
| `neighbour` | 右邻（C） | 断言 `activeDocKey` 精确等于 C 的键 |
| `left_neighbour` | 左邻（A） | 断言 `activeDocKey` 精确等于 A 的键 |

> 注意 `history` 与 `left_neighbour` 在「关 B」这一例里结果相同（A），
> 因此测试用例**必须**另取一个能区分二者的场景（例如只有两个标签 A、B，关 B：
> `history` → A、`left_neighbour` → 无左邻 → 需回退到 B 之外或保持 A），
> 否则两条策略的判据会碰巧同时成立（等价变异，见 HANDOFF §4 ㉒）。

#### D-4 切走时，脏标签页是否留底快照 —— **待 team-lead 拍板**

**QA 倾向：留底，与既有 `switchFile()` 语义严格一致。**

依据：`useDocumentState.js:175-178` 的 `switchFile()` —— `if (dirty.value) await writeSnapshot(true)`，
其注释原文是「当前文档为脏 → 先强行写一份快照留底（旧稿内容此刻还在编辑器里，错过这一刻就永远写不回去了）」。
多标签页下「切走」并不丢弃内容（tab 还在），但**保持同一语义**可让既有快照回归集零改动复用，
且 Go 侧按内容哈希去重（`writeSnapshot` → `SnapshotWrite`），来回切同一份未改内容不会产生快照膨胀。

#### D-5 切走再切回，哪些状态保留（逐条矩阵）—— **待 team-lead 拍板**

| 状态 | 建议 | 理由 |
|------|------|------|
| 文档内容 | **保留** | tab 持有自己的 EditorState |
| 光标位置 / 选区 | **保留** | 同上（选区在 EditorState 内）。**竞品实证**：Obsidian 论坛痛点帖「切回笔记回到文档开头」 |
| 撤销栈 | **保留，且不跨标签互通** | 撤销栈在 EditorState 的 history 字段内，随实例走；在 A 里 ⌘Z 撤不到 B |
| 滚动位置 | **保留**（由 advisory 升为**必须**） | 竞品实证同上：Obsidian 痛点「切回笔记回到文档开头」「多标签只有最后停留位置被记住」。**与 PM 的 R2 要求一致** |
| 语法高亮 / 表格渲染 / 图片装饰 | **应该**重算（不缓存旧 DOM） | 装饰是 EditorState 的派生值；换 state 即重算。**注意**：`image-asset-context.test.mjs` 证明了 CM 会复用旧 DOM（`eq()` 判定），切 tab 必须让 `eq()` 失配，否则会定格在旧 tab 的图片地址上 |
| 查找 / 搜索面板状态 | **不保留** | 属视图级状态，跨 tab 残留是缺陷 |
| 大纲 / 表格提示 / 字数 / 行列号 | **不保留**（即必须重算） | 都是当前文档的派生值，残留即缺陷（AC-46~AC-51） |

#### D-6 关闭窗口的确认粒度 —— **待 team-lead 拍板**

**QA 倾向：一次确认覆盖全部脏标签，提示文案里说明「有 N 个文档有未保存更改」。**

理由：现状是**一次**系统确认框（`app.go:346-358`，`runtime.MessageDialog`）。
若改成每个脏 tab 弹一次，用户关窗要点 N 次 —— 体验退化，且在 macOS 上系统对话框是模态的。
聚合确认需要 Go 侧拿到「有几个脏的」这个计数，故 `SetDirty` 升级为携带计数的镜像（或映射）。

#### D-7 标签栏是否可隐藏（显隐偏好） —— **待 team-lead 拍板**

**QA 倾向：做，且偏好项**必须**有单一写入来源。**

竞品实证：MarkText issue #5581「Toggle Tabbar 状态在打开第二个文件后被自动重置」
（https://github.com/marktext/marktext/issues/5581）——
手动隐藏标签栏后，打开第二个文件标签栏自己又冒出来。

根因形态与本仓高度同型：本仓的偏好真源是 `themes/prefs.js`，
且 MEMORY 明确记着「`--zoom-scale` 的唯一写入者是 `composables/usePrefs.js`」
—— 同一个变量有第二个写入者就会跳变。标签栏显隐**必须**遵守同一纪律：
**唯一写入者** + 打开文件/新建标签等路径**不得**顺手把它置回默认。

AC 见 AC-60。**若 PM 决定不做显隐偏好**，AC-60 降级为「标签栏恒显」并**显式记录**，不得默认沉默。

#### D-8 「恢复已关闭标签」是否还原光标 / 滚动位置 —— **待 team-lead 拍板**

**QA 倾向：还原。**

竞品实证：Sublime 社区反馈「Ctrl+Shift+T 只恢复文件，不保留关闭前光标位置」——
即恢复出来的文档回到开头，用户还得再滚回去。
本仓已有「每 tab 记 position」的机制（若 D-5 采纳），恢复标签时**复用同一份位置数据**即可，成本极低。

AC 见 AC-62。**注意**：若 D-5 最终不采纳「保留滚动位置」，则 AC-62 降级为「至少还原选区」。

#### D-9 侧栏是否提供「打开的文档」列表 —— **待 team-lead 拍板**

**QA 倾向：若做，必须与标签栏能力对等**（右键菜单 / 中键关闭 / 拖拽重排）。

竞品实证：MarkText issue #5686「标签栏隐藏时侧栏 Opened files 列表缺这些操作」
（https://github.com/marktext/marktext/issues/5686）—— 同一个东西两套能力，用户会记错。

本仓现状：侧栏只有「文件 / 大纲」两个 tab（`App.vue:105-110`），**没有**「打开的文档」列表。
故 AC-61 是**条件式**的：**若**实现该列表，**则**必须能力对等；
**若**不实现，**不得**出现「侧栏列出了打开的文档但不能关闭/重排」的半吊子形态。

#### D-10 关闭标签 / 关闭窗口的键位 —— **待 team-lead 拍板**

**约束**：⌘W **不可占用**（team-lead 约束 3，macOS 系统「关窗口」语义 + Wails 窗口行为）。

## 3. 验收标准（EARS）

### 3.1 写法口径

- 句式：`<触发条件/状态>，Then Inkmark <行为>`。
- **必须** = 阻断项（不满足即 P0/P1 缺陷，上线前必须清零）。
- **应该** = 非阻断建议（advisory，记入待办）。
- 模式标注：`事件驱动` / `状态驱动` / `非期望行为` / `通用` / `可选特性`。
- 每条 AC 都标注**可自动化层级**：`L1/L2`（node:test）/ `L3`（CDP 探针）/ `L4`（真机目视）。

### 3.2 A 组 · 标签的开设与复用

| AC | 模式 | 验收标准 | 层级 |
|----|------|---------|------|
| AC-01 | 事件驱动 | When 用户触发「新建文档」命令，Then Inkmark **必须**新开一个标签页、将其设为激活标签，且该标签的文档内容为空、路径为空（未落盘）。 | L2 |
| AC-02 | 事件驱动 | When 用户打开一个**尚未打开**的文件，Then Inkmark **必须**新开一个标签页承载它、将其设为激活标签，且该标签的路径等于该文件的绝对路径。 | L2 |
| AC-03 | 事件驱动 | When 用户打开一个**已经打开**的文件，Then Inkmark **必须**复用既有标签页并将其设为激活标签，**标签总数不得增加**。 | L1 |
| AC-04 | 事件驱动 | When 用户从文件树点击一个已在标签页中打开的文件，Then Inkmark **必须**激活既有标签页，**不得**新开重复标签（与 AC-03 同语义，入口不同）。 | L2 |
| AC-05 | 通用 | Inkmark **必须**以文档键（`docKey`）而非显示名区分标签页；两个不同目录下**同名**的文件**必须**是两个独立标签页。 | L1 |

> AC-03/AC-04 的判据不能写成「标签数 == 1」这种计数式断言（会碰巧成立）。正确判据：
> 打开前后的**标签集合（docKey 列表）**逐项相等，且 `activeDocKey` 指向被打开的那个。

### 3.3 B 组 · 标签切换的状态保真

| AC | 模式 | 验收标准 | 层级 |

#### 3.11.1 A 组 · 按住循环必须遍历整个 MRU 列表（优先级**高于** AC-28 落点策略）

| AC | 模式 | 验收标准 | 层级 |
|----|------|---------|------|
| AC-74 | 通用 | While 存在 A、B、C 三个标签、且 MRU 顺序为 `[C, B, A]`，When 用户**按住**切换键（一次 keydown→keyup 周期内）并连续触发 ≥3 次 keydown，Then 被激活过的标签**必须包含 A、B、C 三个不同的标签**，**不得**只在两个标签之间反复横跳。**判据**：断言「被访问过的标签集合 === {A, B, C}」（集合相等），**不得**断言最终停在哪个标签（落点取决于最后一次 keydown 的时序，不稳定）。 | L1 / L2 / L3 |
| AC-75 | 通用 | Where 切换浮层（Tab Switcher）渲染失败因而走**降级路径**（直接切换、不显示浮层），When 用户按住切换键连续触发 ≥3 次 keydown，Then 降级路径**必须**使用与浮层路径**同一份 MRU 快照**，访问过的标签集合**必须**同样包含全部标签。**不得**因降级而退化成「两个标签之间抖动」。 | L1 / L2 |
| AC-76 | 通用 | When 用户在**两次独立**的切换调用之间切换（第一次松开、第二次重新按下），Then 第二次**必须**回到「上一个访问过的标签」（即「上上个文件」）。**这是正确的 MRU 语义，不是缺陷** —— 本条的作用是**防止把正确行为当 bug 修**：实现方与测试方**都不得**据此把「两次独立调用回到上上个」判为失败。 | L1 / L2 |

> **AC-74 的根因（架构方案 §4.5 + §4.10 互相打架）**：
> 架构 §4.5 写「每次激活把目标移到 MRU 头部」，§4.10 写「keydown 重复触发 → 在 MRU 顺序里循环移动高亮项」。
> 两者组合 ⇒ MRU = `[C, B, A]` 时：keydown1 → 切到 B → MRU 变 `[B, C, A]`；
> keydown2 → 切到 C → MRU 变 `[C, B, A]`；keydown3 → 又切回 B → MRU 变 `[B, C, A]`。
> ⇒ **第三个标签 A 永远够不到**，且现象是「按住只在最近两个标签之间抖动」——
> 切换功能「看起来能用」，但第三个标签不可达，是典型的**静默失效**。
>
> **正解**：单次按住（一个 keydown→keyup 周期内）使用**首次按下瞬间的 MRU 快照**，在快照内循环；
> **下一次独立按住**才重新取快照（这正是 AC-76 保护的行为）。
>
> **判据写法要点**：AC-74 断言的是「**被访问过的集合**」而不是「最终落点」。
> 若断言最终落点，keydown 的时序抖动会让测试**间歇性失败**（flaky）——
> 本仓对 flaky 用例的处置是「让它稳定下来或删掉」，但这里正确的做法是**换成集合断言**
> （HANDOFF §4 ⑱：断言要打在「该路径特有的可观测差异」上）。

> 半角 `dispatchKeyEvent` **验不出**输入法问题 —— 中文输入法中文标点模式下 `/` 产出的是全角 `／`，

>
> **优先级提级理由（PM 明确要求）**：zh-CN 与 ja-JP 是**已发布的两个 locale**，
> IME 是这两个 locale 的**主输入路径** → 这是**三分之二用户主路径上的数据丢失类缺陷**，
> 不是体验问题。且它的缓解措施（切标签前检测 `view.composing`、为真时延迟切换）
> 会**改动切换时序** —— 结论出得太晚可能要**重写时序代码**。
> 故真机清单里它**排第 30 项（最前）**，且必须进 macOS 段（见 §7.2）。
>
> **架构侧对应**：架构风险 **R10**（IME 合成中切标签），缓解 = 检测 `view.composing` 为真时延迟切换。
> 自动化**部分守得住**（合成态可测），**真机的 IME 行为必须真机验**。

### 3.14 L 组 · 脏标记视觉形态（dirty / error 必须可区分）

> team-lead 裁决：保留 per-tab 脏标记，沿用 ADR-005 语义（`dirty ⟺ 内存 ≠ 磁盘`）不变，
> 但**必须区分两种状态**：
> - **dirty**（内存 ≠ 磁盘）：因 800ms 自动保存，通常转瞬即逝 → 视觉须**克制**（低调小圆点），
>   **不得**做成高对比白点；
> - **error**（自动保存失败 / 只读目录 / 未落盘且有改动）：**异常态**，标记必须与 dirty **明确可区分**。
>
> 竞品依据：Obsidian 刻意不做常驻脏标记（持续自动保存，星号只闪不到 1 秒即无意义）；
> VS Code 用常驻白点。本仓因已有 800ms 自动保存，dirty 窗口本就极短。

| AC | 模式 | 验收标准 | 层级 |
|----|------|---------|------|
| AC-67 | 通用 | While 标签处于 **dirty** 态，Then 其标记**必须**是低调形态：颜色对比度落在「可辨认但不抢眼」区间。**判据**（可机检，不许肉眼描述）：标记的计算色**必须**取自 `--meta` 级 token，且其对标签底色的对比度**必须** ≥ 3:1（WCAG 1.4.11 非文本对比下限），且**必须** < `--danger` 级 token 的对比度（否则就是高对比异常态的表现）。 | L2（静态）/ L3（计算色） |
| AC-68 | 通用 | While 标签处于 **error** 态，Then 其标记的计算色**必须**与同标签 dirty 态的计算色**精确不等**（不是「看起来不同」），且**必须**取自 `--danger` / `--warn` 级 token。 | L3（计算色）+ L2（静态） |
| AC-69 | 非期望行为 | If 同一标签同时满足 dirty 与 error 两个条件，Then 界面**必须**只呈现**一种**标记（error 优先），**不得**两个标记并存、**不得**一个 CSS 类覆盖另一个。 | L2 |
| AC-70 | 通用 | 标签标记的颜色**必须**全部来自 `frontend/src/themes/tokens/design-tokens.css` 已有的 token，**不得**出现任何字面色值（`#hex` / `rgb()` / `hsl()`），**不得**新增颜色常量。**判据**：静态扫描标签相关 CSS，剥注释后不得出现字面色值（复用 `helpers/lexer.mjs` 的剥注释器）。 | L2（静态机检） |
| AC-71 | 通用 | While 标签**未落盘**（`filePath` 为空）**且**有未落盘改动，Then 该标签**必须**呈 **error** 态标记（因为它**永远无法自动保存** —— `useDocumentState.js:136` 的 `markDirty` 只在 `filePath` 非空时才调度自动保存）。该标记**不得**被误呈现为普通 dirty（否则用户会以为「等一下就好了」）。 | L1 / L2 / L4 |
| AC-72 | 通用 | Inkmark **必须**为 dirty / error 提供**颜色之外**的可机检语义信号：标签元素的 `data-state` 属性值（或 `aria-label` / `title` 文案）**必须**在两态下不同。**不得**只靠颜色区分两种状态 —— WCAG 1.4.1「Use of Color」要求；且 §3.13 的对比度实算已证明「靠对比度倍数区分」在两个主题下都不可靠（只有 1.6~1.8 倍）。**判据**：静态扫描标签栏模板，断言 dirty 元素与 error 元素的 `data-state` 值**精确不等**。 | L2（静态）/ L3 |
> **颜色 token 的可用性与对比度（本轮实算，2026-10-28，WCAG 相对亮度公式）**：
>
> | 主题 | token | 值 | 对 `--bg` | 对 `--surface` |
> |------|-------|----|-----------|--------------|
> | 浅色 | `--meta` | `#8A8D99`（`design-tokens.css:48`） | **3.31:1** | **3.11:1** |
> | 浅色 | `--danger` | `#B23B31`（`:63`） | **5.89:1** | **5.55:1** |
> | 深色 | `--meta` | `#6A6D78`（`:104`） | **3.53:1** | **3.66:1** |
> | 深色 | `--danger` | `#DF7268`（`:119`） | **5.85:1** | **6.06:1** |
>
> 四个值都 ≥ 3:1（WCAG 1.4.11 非文本对比下限达标）。
>
> **但对比度倍数不可当判据**：浅色下 `--danger / --meta` = 5.55/3.11 = **1.78 倍**，
> 深色下 = 6.06/3.66 = **1.66 倍** —— 差距在两个主题里都只有 1.6~1.8 倍，
> 而 `--meta` 与 `--fg-2`（浅色 `#40434E` / 深色 `#B4B7C2`）这类**相邻** token 也可能拉开相近的比值。
> 故 AC-68 的判据**必须比对完整 rgb 值（精确不等）或比对具体 token 的解析值**，
> **不得**用「对比度差 N 倍」当判据；且真机目视项 43 **必须**在深色主题下再验一次（见 §8.3 R-16）。
>
> **色彩语义**：深色主题里区分 dirty 与 error 靠的是**色相**（灰 `#6A6D78` vs 红 `#DF7268`），

> （`data-state` / `aria-label`）是必需的，不是锦上添花。

> 不动那个分歧；但实现方若要统一，需**显式**改 ADR 或改实现，不许默默继承任一侧。

## 5. 测试计划

### 5.1 分层与判据原则

| 层 | 载体 | 数量定位 | 能抓什么 | 抓不到什么 |
|----|------|---------|---------|-----------|
| L1 单元 | `frontend/tests/*.test.mjs`（`node:test`） | 大量 | 纯逻辑不变量、状态机、撤销栈深度、脏标记归属 | 真实浏览器事件、真实 DOM 布局 |
| L2 集成 | 同上，但用**真实模块 + 注入式依赖** | 中等 | composable 级接线、模块级单例的跨 tab 行为、Go 镜像调用序列 | 真实 CM 视图的 DOM 重建 |
| L3 探针 | `scripts/probe/probe-multi-tab.mjs`（CDP + 无头 Chrome） | 少量 | 真实按键、真实 CM 视图、真实 DOM、装饰重建 | WKWebView 特有行为（剪贴板、输入法、系统对话框） |
| L4 真机 | `docs/HANDOFF.md` §6 + `docs/qa/visual-checklist.html` | 少量 | 观感、手感、系统对话框、多窗口 | —— |

**贯穿四层的判据纪律**（本仓铁律）：

- 断言打在**该路径特有的可观测差异**上。禁止只断言「条数 / 计数 / 布尔」。
- 「不许弄丢」的接线一律从**运行期数据结构**读回，不许用源码正则 pin
  （HANDOFF §4 ⑲；正确形态见 `image-asset-context.test.mjs` 用 CM 自己的 `RangeSet.compare`
  判「CM 会不会重建 DOM」）。
- 每个新判据配**探测器自检**（同一输入必须「无差异」，改动后必须「有差异」），防「比较器口径不对 → 假绿」。
- 失败路径必须让**失败条件成为显式入参**（HANDOFF §4 ⑰），不许在用例里先设全局状态再调被测函数。

#### ② `frontend/tests/tab-activate.test.mjs`（L1，真 EditorState）

测什么：切换的状态保真（AC-06~AC-11）。
手法：**真 `EditorState` + 真 history 扩展**（`@codemirror/commands` 的 `history()`），
用 `undoDepth(state)` / `redoDepth(state)` 读**运行期**的撤销栈深度
（这是「从运行期数据结构读回」的形态，对应 HANDOFF §4 ⑲ 的正解）。

| 用例 | 判据 |
|------|------|
| 切走再切回，内容逐字相同 | `state.doc.toString()` 与切走前快照**逐字相等** |
| 光标恢复 | `state.selection.main.head` 精确等于切走前的值 |
| 撤销栈保留 | 切走前 `undoDepth >= 2`；切回后 `undoDepth` 仍 `>= 2`（**不是**「大于 0」） |
| 撤销栈不跨 tab 互通 | 在 A 上执行 `undo(state)` 后，**B 的** `state.doc.toString()` 逐字未变 |
| 编辑不串台 | 在 A 上 dispatch 插入后，B 的 doc 逐字未变 |

#### ③ `frontend/tests/tab-dirty.test.mjs`（L1/L2）

测什么：脏标记归属与 Go 镜像（AC-13~AC-17、AC-22、AC-23）。
手法：**注入式依赖**（把 `SetDirty` 之类的 Go 绑定作为可记录的依赖注入，而不是去 mock 全局）。

| 用例 | 判据 |
|------|------|
| 仅当前 tab 脏 | 断言**逐 tab 的布尔值**：`dirtyOf(A) === true && dirtyOf(B) === false`（不是「脏标记个数 == 1」） |
| 切走再切回脏仍在 | 切走前后 `dirtyOf(A)` 逐字相等（`true === true`） |
| 保存只清该 tab | 保存 A 后 `dirtyOf(A) === false` 且 `dirtyOf(B) === true`（B 先编辑过） |
| 聚合镜像 | 记录的 Go 镜像调用序列里，最后一次的聚合值 === `true`；清掉 A 后 === `false` |
| 全干净时聚合为假 | 断言镜像值 `=== false`（防止「always true」的假实现碰巧通过） |
| 变异自证（红） | 把 dirty 改成模块级单值 → 切 tab 后断言 `dirtyOf(B)` → **必须报红** |

#### ④ `frontend/tests/tab-autosave.test.mjs`（L1/L2，**最高优先级**）

测什么：自动保存隔离与写盘单元同源（AC-18~AC-21）。
手法：**假定时器注入**（`setTimeout` / `clearTimeout` 作为显式入参，绝不用真等 800ms）+
**写盘调用记录器**（记录每次 `(path, content)` 二元组）。

| 用例 | 判据 |
|------|------|
| 写盘单元同源 | 断言记录的 `(path, content)` 二元组：`content` 必须是**该 path 对应 tab** 的内容。断言写成「每条记录都满足 `content === tabs[docKeyOf(path)].content`」，不是「记录条数 == 1」 |
| 后台 tab 触发时不写激活 tab | 切到 B 后触发 A 的定时器 → 记录里 `path` 是 A 的路径（精确相等），**且** B 的路径从未出现在记录里 |
| 写盘期间被再次编辑 → 保持脏 | 在 `WriteFile` 的 promise 未 resolve 时再 dispatch 一次编辑 → 该 tab 的 dirty 仍为 `true`，且保存态为「未保存」 |
| 写盘期间切到别的 tab → **不得**误判 | 写 A 期间切到 B 并编辑 B → A 的 dirty 判定**只**看 A 的内容变化（不得因为 B 变了就把 A 判成「还在变」） |
| 关闭 tab 后不得再写盘 | 关闭 A → 触发 A 的遗留定时器 → 写盘记录**不得**新增 A 的条目 |
| 变异自证（红） | 注入「autoSave 忽略所属 tab，一律用激活 tab 的 path + content」→ 必报红（这是最可能真实发生的错写盘） |
| 变异自证（红） | 注入「写完后拿激活 tab 的当前内容做比对」→ 必报红 |

#### ⑤ `frontend/tests/tab-close.test.mjs`（L1/L2）

测什么：关闭单个标签（AC-24~AC-31）。
手法：确认弹层做成**可注入依赖**（如 `confirmDiscard(tabInfo)` 返回 `'cancel' | 'discard'`），
测试自己 stub 它并**记录调用参数**。

| 用例 | 判据 |
|------|------|
| 干净 tab 直接关 | 确认回调**调用次数 === 0**（这是「未发生」的特有差异，不是「条数」） |

| 资源清理 | 关闭后触发全部遗留定时器 → 写盘记录不得新增；表格提示 `tableHint.value === null` |

### 6.5 变异自证的执行纪律

- 变异一律**在内存里改字符串**（`tdz-order.test.mjs:6` 的纪律：一时刻只允许一个人写仓库）。
- 每次变异后必须 `git diff --stat` 证明零残留。
- 变异自证结论要区分**三种「不报红」**（等价变异 / 测试打错位置 / 真没守住），
  并把「等价变异」从判据里**删掉**而不是留着自我安慰（HANDOFF §4 ㉒ 原文口径）。

### 8.2 探针环境的不构模风险（必须写进探针文件头）

|---|--------|---------|------|
