# ADR-004: 快捷键全量分配表与冲突消解（含 D-4）

## Status

Proposed (**2026-10-01**) —— 待 team-lead 终审。

**已裁决项（team-lead，2026-10-01）**：**阅读模式 = `⌘4`，废弃候选 `⌘⇧R`**。裁决理由：`⌘1/2/3` 已确立「视图态」族，阅读模式属同一语义层（切换「看什么」），应同族；`⌘⇧` 前缀在本项目已被占用为「叠加态」（`⌘⇧F` 专注、`⌘⇧L` 主题切换），混用会造成语义污染；`⌘⇧R` 在浏览器语境里惯例是强制刷新，易误触。本 ADR 已按此裁决更新（见 §二 视图菜单、§三 冲突消解、§Consequences 负面 2）。

约束来源：`docs/spec/DECISIONS-phaseC-v1.md` §二 **D-4（已拍板，不可再议）**——「⌘B 保留『大纲』，加粗改用 ⌘⇧B」。

## Background

Phase C 新增两类快捷键需求：

1. **WYSIWYG 即时模式**需要富文本内联/块级格式命令（加粗、斜体、删除线、行内代码、链接、标题、列表、引用、代码块）。
2. **阅读模式**（P0）需要一个入口键。

现有键位（来自 `main.go:69-92`，`BuildMenu` 实测行号）与既有 `Esc`（`App.vue:297-299`）：

| 键 | 行为 | 位置 | 证据 |
|---|---|---|---|
| ⌘O | 打开文件 | 文件菜单 | `main.go:70` |
| ⌘⇧O | 打开文件夹 | 文件菜单 | `main.go:71` |
| ⌘S | 保存 | 文件菜单 | `main.go:73` |
| ⌘⇧S | 另存为… | 文件菜单 | `main.go:74` |

| ⌘⇧F | 专注模式 | 视图菜单 | `main.go:88` |

冲突盘点结论：**唯一已知冲突是 ⌘B**（DECISIONS §五 第 2 条），已由 D-4 消解。其余新增键位当前均**未被占用**。另有两点需显式回避：`⌘H`（macOS 系统「隐藏应用」）、`⌘Q`（退出）、`⌘W`（关窗）——**不得占用**。

## Decision

### 一、快捷键的承载机制：**全部走 Go 原生菜单 accelerator**（单一真源）

沿用既有架构（`App.vue:464-472` 注释：「快捷键由菜单 accelerator 承担，菜单会先于 WebView 消费按键，因此前端不再单独监听 keydown，避免同一次按键触发两次」）。

- 文件 / 视图 / 新增的**格式**菜单项，一律在 `main.go` 的 `buildMenu` 中经 `keys.CmdOrCtrl` / `keys.Combo` 声明，回调只 `runtime.EventsEmit`，业务在前端处理。
- **格式命令也走菜单事件**（前端把事件映射到 CodeMirror 命令），**不另在 CodeMirror `keymap` 里重复绑定**。原因：macOS 菜单 accelerator 会在 webview 之前消费按键，若菜单与 CM keymap 绑同一键，CM 永远收不到——重复绑定会造成「看起来配了、其实不触发」的静默失效（呼应 `generated-code-failure-modes.md §1 沉默逻辑错误`）。
- 例外：`Esc` 继续由前端 keydown 处理（菜单 accelerator 无法表达「无修饰键的 Esc」，且 `App.vue:296` 已说明该理由）。

Wails `keys` 修饰键常量（实测 `pkg/menu/keys/keys.go:11-22`）：
`CmdOrCtrlKey`（mac=Cmd，其余=Ctrl）、`OptionOrAltKey`（mac=Option，其余=Alt）、`ShiftKey`、`ControlKey`。

### 三、冲突消解记录

| 冲突 | 消解 | 依据 |
|---|---|---|
| ⌘B 双击用途（大纲 vs 加粗） | **大幅保留，加粗改 ⌘⇧B** | D-4（已拍板） |
| ⌘1…⌘6 标题 与 ⌘1/2/3 视图三态 | 标题改 **⌘⌥1…⌘⌥6** | 视图三态已发布，零回归优先 |
| ⌘⇧H 导出 HTML 与「插入水平线」常见键 | 水平线**不分配键**（菜单可点） | 避免与已发布 ⌘⇧H 冲突 |
| 阅读模式入口键（⌘4 vs ⌘⇧R） | **定为 ⌘4；`⌘⇧R` 明确不予采用**（本表全表无任何 `⌘⇧R` 绑定） | team-lead 裁决 2026-10-01：视图态族一致性 + 避开「⌘⇧=叠加态」语义污染 + ⌘⇧R 在浏览器惯例为强制刷新（易误触） |
| ⌘P 惯常=打印 | 本项目 **⌘P=一键导出 PDF**（D-3 替代打印） | 主动重映射，见 §四 |
| ⌘E 惯常=「用所选内容查找」 | 本项目无查找功能，⌘E 暂给「行内代码」；**未来若加查找，须让 ⌘E 回归查找、行内代码迁移** | 预留说明，防后续踩 |

**无重复键**：上表所有组合互不相同（已逐条比对）。新增键位与 macOS 系统保留键（⌘H/⌘Q/⌘W/⌘Tab/⌘Space）无交集。

### 四、跨平台（CmdOrCtrl → Ctrl）注意事项

`keys.CmdOrCtrlKey` 在非 macOS 平台映射为 Ctrl，故上表新增项在 Windows / Linux 变为：

`Ctrl+Shift+B` / `Ctrl+I` / `Ctrl+Shift+X` / `Ctrl+E` / `Ctrl+K` / `Ctrl+Alt+1…6` / `Ctrl+Shift+7,8,9` / `Ctrl+Shift+.` / `Ctrl+Alt+C` / `Ctrl+4`。

- **Ctrl+Alt+N（即 AltGr+N）风险**：在部分欧洲键盘布局中 `AltGr` = `Ctrl+Alt`，可能影响 `⌘⌥1…6` / `⌘⌥C` 的输入。项目以 macOS 为第一形态，此为**已知跨平台约束**，非阻塞；若日后主攻 Windows，需把标题/代码块改绑到无 AltGr 冲突的组合。
- 不得占用 Windows 系统键：`Ctrl+Alt+Del`、`Ctrl+Shift+Esc`（本表均未触及）。
- 菜单文案：macOS 显示 ⌘ 系符号，Windows/Linux 显示 `Ctrl+…`，由 Wails 菜单层按平台渲染，无需前端分支。

## Consequences

**正面**
- **D-4 零回归**：⌘B 行为不变；加粗迁移到 ⌘⇧B，不触碰已发布键位。
- **单一真源**：所有快捷键集中在 `main.go` 的 `buildMenu`，与既有架构一致；菜单即「快捷键说明书」，可发现性好。
- 新增格式键对齐行业惯例（Google Docs 7/8/9、Typora ⌘⌥C、Web 系 ⌘K），降低学习成本。
- 显式记录「预留让位」（⌘E 给未来查找），避免后续静默冲突。

**负面 / 风险**
1. **菜单 accelerator 无法按上下文禁用**（中）：格式键在预览/阅读态按下仍会触发事件。**缓解**：前端收到格式事件时，若编辑器不可聚焦或处于非编辑态，静默忽略（不报错、不改数据）；并在故事验收里覆盖该分支。
2. **⌘4 阅读模式：已由 team-lead 裁决为终版**（2026-10-01），不再是「顺延」待确认项。裁决要点：`⌘1/2/3` 构成「视图态」族，阅读模式属同一语义层（切换「看什么」），应同族；`⌘⇧` 前缀已被「叠加态」（`⌘⇧F` 专注、`⌘⇧L` 主题切换）占用，混用会造成语义污染；`⌘⇧R` 在浏览器语境惯例为强制刷新，易误触，故**废弃**。阅读模式实现为**第 4 视图态**（非叠加态）；`Esc` 退出后回到**进入前的视图态**，行为与专注模式一致（`App.vue:275-294` 的 `modeBeforeFocus` 机制可直接复用为 `modeBeforeReading`）。
3. **AltGr 冲突**（低，仅非 mac）：见 §四。
