# ADR-005: 未保存状态（dirty）语义 —— 单一不变量「内存文档是否落后于磁盘」

## Status

**Accepted (2026-10-02)**。

约束来源：Phase C「未保存关闭拦截」（commit `feat(app): 未保存关闭拦截`）落地后，该状态横跨三处（前端 `dirty` → `SetDirty` IPC → Go `OnBeforeClose`），但原先只有一句「未保存更改标记」的注释，**只描述了数据流向、没有定义这个布尔量表示什么**。team-lead 指示将其语义固化，以防后续扩展（多窗口 / 后台常驻）时语义漂移。

## Background

Phase C 引入关闭拦截：前端持 `dirty`（`frontend/src/composables/useDocumentPersistence.js`），经 `SetDirty`（`app.go`）同步到 Go，`OnBeforeClose`（`main.go` 挂载）据此决定是否弹系统确认对话框。

一个布尔量被三方共享却语义未写死，风险是：未来任何一个新功能（撤销栈、协作同步、多窗口、快照策略）都可能按各自的理解去置位它，产生「同一字段多种含义」的隐性冲突。典型坏例：把「有未提交的编辑操作」或「上次快照之后有改动」也塞进同一字段。

## Decision

### 一、唯一不变量

> **`dirty === true` ⟺ 编辑器当前内存中的文档内容 与 该文档在磁盘上的内容 不一致。**

- 文档在磁盘上**没有副本**（从未落盘的新文档、另存为被取消）时，视为「不一致」→ `dirty = true`。
- 两者一致（保存成功）→ `dirty = false`。

### 二、语义边界（明确「不是什么」）

| 不是 | 说明 |
|---|---|
| 不是「是否有未提交的编辑操作」 | 撤销栈深度与 `dirty` 无关。编辑后又手工改回原样，`dirty` 仍为 `true`（实现不比对内容）。这是**已知的保守偏差**，方向安全：宁多问一次，不静默丢数据。 |
| 不是「是否正在写盘」 | 写盘过程由 `saveState`（`unsaved`/`saving`/`saved`/`error`）表达，是另一状态机，二者正交；`saving` 期间 `dirty` 可仍为 `true`。 |
| 不是「是否有未生成的快照」 | 快照与自动保存解耦（AC-14），快照时钟不参与 `dirty`。 |
| 不是「窗口 / 应用级的全局脏」 | 见 §四。当前实现等价于「当前文档脏」，因为应用同一时刻只持有一份文档。 |

### 三、生命周期（谁、在何处置位）

真源在前端（`useDocumentPersistence.js`），Go 侧只做**镜像与消费**。

| 事件 | 位置 | dirty |
|---|---|---|
| 编辑 | `App.vue onDocChange` → `persistence.markDirty()` | → `true` |
| 自动保存成功（800ms 防抖） | `autoSave()` | → `false` |
| 自动保存失败（只读目录等） | `autoSave()` catch | 保持 `true`（确实落后于磁盘，`saveState='error'`） |
| 显式保存 `⌘S` | `saveFile()` | → `false` |
| 另存为成功 | `saveFileAs()` | → `false` |
| 另存为取消 | `saveFileAs()` 早返回 | 保持原值 |
| 打开文件 / 切换文件 | `loadDocument()` → `resetSession()` | → `false`（内存 := 磁盘） |
| **恢复历史快照** | `restoreSnapshot()` → `markDirty()` | **→ `true`**（内存 := 历史内容 ≠ 磁盘；随后自动保存） |
| 导出 HTML / PDF | — | 不变（导出不改文档，不进 `dirty`） |

**一致性要求（硬约束）**：任何改动文档内容的代码路径，**必须显式声明它对 `dirty` 的影响**——要么标脏、要么在确实已落盘时归零；**不得默认继承上一状态的 `dirty` 值**。

理由是这类路径最易产生语义缺口：`syncAfterDocReplace`（`App.vue`）被「打开文件」与「恢复快照」共用，而两者的期望相反——打开文件是「内存 == 磁盘、不应脏」，恢复快照是「内存 ≠ 磁盘、应脏」。共用一个不声明 `dirty` 的回调，就必然漏置位。

> **补记（本条固定时发现并修复）**：`restoreSnapshot` 原先未置脏，导致恢复快照后 ①不触发自动保存 ②关闭窗口不拦截 → 恢复的内容可能被静默丢弃。已按本不变量补 `markDirty()`。

### 四、扩展路径（多文档 / 多窗口 / 后台常驻）

当前 `dirty bool` 是单值，等价于「当前文档脏」。**升级方向**：替换为按文档键的映射（`docKey → dirty`，`docKey` 沿用 `snapshot.go` 的 `SnapshotDocKey` 派生规则），`OnBeforeClose` 遍历所有已打开文档，任一脏则拦截。

**明确禁止**：在这个布尔量上叠加第二种含义（如「或有未保存的窗口布局」）。新语义必须开新字段，不得复用 `dirty`——这是本 ADR 存在的首要目的。

### 五、跨进程传输约定

- 前端 → Go：`SetDirty(bool)`，由前端 `watch(dirty)` 边沿触发（仅在**变化**时调用）。
- Go 侧不自行推断、**不读盘比对文件内容**，只镜像。
- 读写不加锁：均发生在 Wails 主事件循环序列内，最坏是一次多余的确认框，不影响数据安全。
- 前端启动时 `dirty = false`，与 Go 零值一致，无需首次同步。

## Consequences

**正面**

- 布尔量语义单义，任何新功能都能一句话判断「该不该动它」。
- 「改动文档的路径必须显式声明 `dirty`」被定为硬约束后，缺口可被评审/自查发现——本条规定立即发现了 `restoreSnapshot` 的既有缺口。
- 扩展路径预先钉死（映射化 + 禁止语义叠加），多窗口改造时不必重新设计。
- 保守偏差方向统一为「宁多问一次」：与 `OnBeforeClose` 在对话框异常时返回阻止的处理一致。

**负面 / 风险**

1. **不比对内容 → 误报**（低）。编辑后手工改回原样，`dirty` 仍为 `true`，会多弹一次确认。取舍：比对内容需读盘 + 逐字节 diff，成本高于收益；个人写作工具场景下误报代价仅一次点击。
2. **恢复快照 = 立即自动保存**（低）。`markDirty()` 会在 800ms 后把恢复内容写盘。这符合「恢复即一次编辑」的定位，且用户仍可 `⌘Z`。替代方案（为恢复单独引入「暂停自动保存」态）**不采纳**——会破坏「自动保存是常态」的一致性。
3. **单文档假设内嵌**（中，仅多窗口时暴露）。见 §四，已有明确升级路径。
