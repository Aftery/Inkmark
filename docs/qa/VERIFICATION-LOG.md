# Inkmark · 真机目视验收记录（append-only）

> **这份文件是什么**：`docs/HANDOFF.md` §6 那些「无法进门禁、只能在真机上肉眼确认」的
> 交互项（窗口拖拽 / 红绿灯留白 / 毛玻璃 / 斜杠面板 / fsnotify 三场景……），
> 在此留下**验过什么、在哪个平台验的、结论如何**的痕迹。
>
> **它和 §6 的分工**：
> - `docs/HANDOFF.md` §6 = **要验什么**（清单的定义与编号，唯一真源）。
> - 本文件 = **验过什么、结论如何**（历史记录，只追加）。
> - 清单的可交互形态 = `docs/qa/visual-checklist.html`（勾选 / 存档 / 导出）。
>
> §6 与本文件所用的编号一一对应；若 `visual-checklist.html` 与 §6 不一致，
> 以 §6 为准，并由 `scripts/verify/verify-visual-checklist.mjs` 报红拦住（防漂移）。

---

## 怎么用（三步）

1. **打开清单**：用浏览器双击打开 `docs/qa/visual-checklist.html`（离线单文件，无需构建）。
2. **在真机上逐项验**：选好平台 / 填验证人 / 日期，逐项勾选结论（未验 / 通过 / 不通过 / 不适用）并写备注。
3. **导出并追加**：点「生成导出 Markdown」→「复制到剪贴板」（或「下载 .md」）→
   把结果**追加到本文件末尾**。

**纪律（重要）**：

- **只追加，不改历史行**。一次验收 = 在文件末尾新增一节，历史记录永不回改。
  若某项结论后来被推翻，**新增一条**说明（带日期），而不是删旧行 —— 保留推翻的轨迹本身就是证据。
- **禁止编造结论**。本文件不预填任何验证结果；`<待填>` 只是模板占位。
  没验过的项就不要写「通过」。
- 同一平台多次验收、或多平台分别验收，各记一节（导出内容里带日期 / 平台 / 验证人，天然可分区分）。

## 记录模板（复制这一节，填好追加到文件末尾）

```markdown
## 真机目视验收记录

- 平台：<待填：macOS / Linux / Windows>
- 验证人：<待填>
- 日期：<待填：YYYY-MM-DD>
- 汇总：已验 <待填> / 22（通过 <待填> / 不通过 <待填> / 不适用 <待填>）

| 编号 | 项 | 结论 | 备注 |
|---|---|---|---|
| 1 | macOS 窗口形态 | <待填> | <待填> |
| 2 | macOS 红绿灯留白 | <待填> | <待填> |
| … | … | … | … |
| 22 | 文件树外部变更监听 | <待填> | <待填> |

> 清单项与编号以 `docs/HANDOFF.md` §6 为准；本记录由 `docs/qa/visual-checklist.html` 导出。
```

> 上面是**空模板**——表格 22 行由清单导出时自动生成，此处 `…` 仅为示意、不必手抄。
> 手写记录时，也请为每个已验项填「结论」，未验项留「未验」，不要把整节里没验的项写成「通过」。
