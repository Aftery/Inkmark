## 0. 为什么单独成文（本文存在的理由）

2026-10-28 的 Phase 1 一致性检查中，**决策被摊在三份文档的三个编号体系里**（架构师 `D1–D8`、测试计划 `D-1–D-10`、team-lead 首轮 `D1–D13`），直接导致：

- **C-3 编号三方撞号** —— 同一件事有三个名字，读者无法判断哪个是权威；
- **C-4 映射表漏 4 行** —— 根因就是「拍板时只看自己手上那一份，漏看了别处的 4 行」。

⇒ **本文件是多标签页决策的唯一真源**（MD = Multi-tab Decision）。其他文档**引用** `MD-xx`，不得**定义**决策。
⇒ 命名空间 `MD-01`…`MD-15` 全局唯一，跨文档、跨成员、跨轮次不得复用。

## 1. 决策清单（MD-01…MD-15）

| 编号 | 议题 | 裁决 | 理由 | 拍板 |
|---|---|---|---|---|
| **MD-01** | 后台标签是否自动保存 | **也自动保存**（选项 a） | 与 ADR-005 §一自洽；既有 800ms 持续写盘语义不变；落盘目标不串（同路径幂等已保证）；反向代价更大 —— 后台标签不保存 = 崩溃即丢稿 | team-lead |
| **MD-02** | 关闭标签的键位 | **`⌘⌥W`**，**不绑定 `⌘W`** | `⌘W` 在 macOS 是「关窗口」的通用肌肉记忆，而 Inkmark 是单窗口应用；绑定它等于把「关标签」与「关窗口」绑成一件事。**不采纳** Zettlr 式改写 `⌘W`（需新增「关窗口」命令 + `⌘⇧W` + 改写既有语义，收益不抵成本） | team-lead |
| **MD-03** | 未落盘新文档的 dirty 初值 | **`false`** | 空文档无内容可丢；按 ADR-005 §一字面则「新建即弹确认」，是噪音。**但必须同批修订 ADR-005 §一**（见 MD-13），**不留口径分歧** | team-lead |
| **MD-04** | 脏 / 异常标记的 token 与互斥规则 | **dirty=`--meta` / error=`--danger` / 未落盘=`--warn`；优先级 error > 未落盘 > dirty，互斥、同一时刻只显示一个** | 见 §2 的实测对比度。维度一「落盘状态」（已落盘 / **未落盘**→`--warn`）、维度二「保存健康度」（正常 / **error**→`--danger`）；两者不并存，用单一优先级裁决 | team-lead |
| **MD-05** | `⌘1..9` 数字直跳第 N 个标签 | **不提供** | `⌘1..⌘6` 已被 `format.h1..h6` 占用、`⌘⌥0` 是正文；`⌘⌥` 家族已有 `⌘⌥F` / `⌘⌥C` / `⌘⌥↑↓`，再加 9 个数字键语义噪声大。MRU + Tab Switcher 浮层 + 鼠标点击已覆盖「精确选一个」 | team-lead |
| **MD-06** | 标签状态持久化 | **localStorage，且必须存未落盘标签的内容**（最近 10 个，超出丢最旧）；**恢复过程只读不写** | 零 Go 改动、与既有偏好存储同源。原方案「未落盘标签不恢复」**不采纳** —— 崩溃后未落盘草稿全丢是明确的差评点（竞品调研实证）。恢复出的标签 `dirty=false`（内存 := 磁盘） | team-lead |
| **MD-07** | 切走时脏标签是否留底快照 | **留底** | 与既有 `switchFile()` 语义一致 —— 旧稿此刻还在编辑器里，错过这一刻就永远写不回去了 | team-lead |
| **MD-08** | 关到只剩一个标签 / 关闭最后一个标签 | **保留一个空文档（沿用现状 `filePath === ''` 空态），应用不退出**；**不新增专用空状态组件** | 退出应用是窗口行为，与标签管理不是一回事；不新增组件是为了保住 `App.vue` 的行数预算（详见架构方案 §4.11） | team-lead |
| **MD-09** | 关闭后的落点策略 | **history（MRU 里上一个访问过的）** | 抄 Zed 的 `activate_on_close = history`；与 VS Code 一致，零争议。**回退规则见 MD-14** | team-lead |
| **MD-10** | Tab Switcher「按住循环」的语义 | **用「按下瞬间的 MRU 快照」** | 若用实时 MRU，循环过程中 MRU 自己会变，循环语义自相矛盾。快照在首次 `keydown` 取一次，`keyup` / 失焦时按快照结算 | team-lead |
| **MD-11** | IME 合成期间切标签 | **P0 级风险，P1 之后立刻真机验证**（不等 P2/P3） | 竞品调研把它列为「键盘、剪贴板、IME 三类高危点」之首；合成期切标签丢预编辑是**静默丢稿**，且**自动化守不住**（headless Chrome 与 WKWebView 不同构） | team-lead |
| **MD-12** | 规格即契约 | **Spec 是唯一真源，AC 编号以 Spec 为准** | 采纳测试计划意见：避免「Spec 与测试计划各写一份 AC 编号」导致两处漂移 | team-lead（采纳 QA） |
| **MD-13** | ADR-005 §一 的修订 | **本轮即改**（不拖到 P6），状态改 `Accepted` → `Accepted (Amended 2026-10-28)` | 与 MD-03 配套。不修订就等于让实现与已接受的 ADR 长期不一致 —— 这正是 ADR-005 存在的目的所反对的。修订措辞见 §3 | team-lead |
| **MD-14** | 落点策略的**回退规则** | **三档（history / neighbour / left_neighbour）统一回退到 history**；**history 无候选时回退到「显示序里的第一个剩余标签」** | **拒绝** neighbour 的两级回退（有右邻取右邻、否则取左邻）—— 它创造了一个**等价变异**：history 与 neighbour 在「切走顺序 == 排列顺序」时行为完全相同 ⇒ 落点判据会假绿（见 §4） | team-lead |
| **MD-15** | 关闭**非激活**标签时，当前激活标签是否改变 | **不得改变** | 关闭后台标签不应把用户从正在编辑的文档里拽走 —— 这是最反直觉的缺陷形态：功能「生效」了，但用户感知为「点了别的东西」 | team-lead |

## 2. MD-04 的实测依据（一次自裁反转的留痕）

team-lead 原裁决「dirty 用 `--muted`」（理由：800ms 内转瞬即逝的红点偏吵）。**产品经理在一致性检查中用实测对比度推翻它**，team-lead 复核 `frontend/src/themes/tokens/design-tokens.css` 后确认成立并**改判**。

> 教训：**涉及视觉「强弱」的裁决，先查 token 的实际对比度，不要凭 token 名字的字面意思。** 「降级反被降级」是凭直觉裁决最容易踩的形态。

### 2.1 实测对比度（对各自 `--surface`，team-lead 独立复算，与 PM 数据完全吻合）

| 主题 | `--surface` | `--meta` | `--muted` | `--danger` | `--warn` |
|---|---|---|---|---|---|
| 浅色 | `#F7F8FA` | **3.11:1** | 4.78:1 | 5.55:1 | 3.52:1 |
| 深色 | `#101116` | **3.66:1** | 5.70:1 | 6.06:1 | 8.58:1 |
| 纸感 | `#F3EEE5` | **3.07:1** | 4.83:1 | 5.63:1 | 4.74:1 |

### 2.2 两个决定性的比值

| 比值 | 浅色 | 深色 | 纸感 | 结论 |
|---|---|---|---|---|
| `--meta` ÷ `--danger` | 0.56× | 0.60× | 0.55× | **明显更弱** ✅ 符合「克制」 |
| `--muted` ÷ `--danger` | 0.86× | 0.94× | 0.86× | **几乎一样强** ❌ 不构成降级 |

`--muted` 被排除。`--meta` 三主题均 ≥3:1（WCAG AA 对非文本图形对象的要求），**纸感主题 3.07:1 仅高出下限 0.07** ⇒ **验收判据必须写明「对 `--surface` 算」且三主题都要验**。

### 2.3 判据形态（对测试计划的硬要求）

**用绝对相等判据，不用相对判据。** 即：脏标记的计算色必须**精确等于** `--meta` 的解析值，异常标记精确等于 `--danger` 的解析值。

> 相对判据（如「≥3:1 且 < danger 的对比度」）**过弱**：任何更浅的颜色都能混过去，将来有人把 `--meta` 换成 `--muted`（4.78:1）仍会通过 —— 而那正是 MD-04 要排除的。

### 2.4 适用范围

MD-04 同时约束**标题栏脏红点**与**标签栏脏标记**（两处 chrome 统一）。`TitleBar.vue` 的 `.tb-dirty` 当前用 `var(--danger)`，**须一并降为 `var(--meta)`**；异常态用 `var(--danger)`。此项属**既有视觉契约变更**，须进目视验收。

## 3. MD-13：ADR-005 §一 的修订措辞

**状态**：`Accepted (2026-10-02)` → **`Accepted (Amended 2026-10-28)`**
**修订位置**：`docs/architecture/ADR-005-dirty-semantics.md` §一「唯一不变量」

原文：

> 文档在磁盘上**没有副本**（从未落盘的新文档、另存为被取消）时，视为「不一致」→ `dirty = true`。

改为：

> 文档在磁盘上**没有副本**（从未落盘的新文档、另存为被取消）时，视为「不一致」→ `dirty = true`。
> **（2026-10-28 修订）例外**：从未落盘**且内容为空**的文档视为「与磁盘一致」→ `dirty = false`。
> 理由：磁盘上既无副本、内容也为空，「不一致」不描述任何可丢失的数据；按字面执行会导致
> 「新建空白文档即弹未保存确认」这一噪音。**一旦该文档有任何输入，立即转为 `dirty = true`**。

**同批还需补**（§一之外）：

- **§四的扩展路径**已被本轮 MD-01…MD-15 实际落地，改写为「**已落地**」并指向本文件；
- **§三生命周期表**新增两行：「新建空白文档 → `dirty = false`」「空白文档首次输入 → `dirty = true`」；
- 补一条**反向禁止**：不得在 `dirty` 布尔量上叠加第二种含义（§四原有条款保留并强化）。

## 4. MD-14 与「等价变异」的系统性风险

一致性复查发现一个**比单个 AC 写错更严重**的问题：**等价变异是系统性的，不是偶发的**。

**成因**：一个「看起来区分性很强」的场景，若**多个不同实现在其上行为一致**，该场景就**丧失区分能力**。

**已识别的等价对**：

| 场景 | 等价实现 | 后果 |
|---|---|---|
| 「切走顺序 == 标签排列顺序」 | `history` 与 `neighbour` 行为完全相同 | 落点判据**假绿** —— 两种实现都过，测不出真实差异 |
| 「按顺序打开文件 A→B→C」 | 打开顺序天然等于 MRU 顺序 | 构造不出「切走顺序 ≠ 排列顺序」 |

**裁决（MD-14）**：

1. **三档落点策略（`history` / `neighbour` / `left_neighbour`）统一回退到 `history`**；
2. **`history` 无候选时**（例如只剩一个标签、或 MRU 里没有别的了）→ 回退到「**显示序里的第一个剩余标签**」；
3. **拒绝** neighbour 的两级回退 —— 它创造了一个等价变异。

**因此，区分性场景必须这样构造**：

- **用「按指定顺序点击标签」构造 MRU**，**不能**用「按顺序打开文件」；
- 场景形态：**3 个标签，排列序 A–B–C，但按 C→A→B 的顺序点击过**（MRU = B, A, C）；
  然后关闭 C ⇒ 期望落点 **B**（MRU 里上一个访问过的），而**不是**排列上的邻居 A。
  - 按「排列相邻」实现的 ⇒ 落点 A ⇒ **报红**；
  - 按「MRU」实现的 ⇒ 落点 B ⇒ 通过。
- 该场景**必须单列为一条测试**，不与通用用例混写（混写就会被「碰巧同过」淹没）。
